# 第一部分 · 功能设计（待审核）

## 1. 一句话

把「在线观看」变成 AVM 里的一等公民：浏览器插件把在线影片、云盘或视频链接连同真实观看时长收进本地片库；一部影片的多个来源自动归一、集中管理、失效可续期，所有观看数据直接进入已有的喜好分析。

## 2. 需求 → 设计对照

| 需求 | 设计如何满足 | 用户可见效果 | 阶段 |
|---|---|---|---|
| 在线看的影片也要保存到 AVM | 插件在影片页面一键收藏，服务端按番号 / 站内 ID / 规范 URL 幂等建片或追加来源 | 不用下载到硬盘，在线影片和本地影片在同一面卡片墙 | 一期 |
| 保存观看时长和所有观看数据 | 插件按真实播放心跳上报，写入现有 `watch_sessions`；暂停、缓冲、拖动不累计 | 口味画像、年度回顾、排行榜、续看、观看历史自动包含在线观看 | 一期 |
| 硬盘空间不足，用云盘 URL / 视频链接当收藏 | 页面 URL、播放 URL（含 m3u8 / 直链）分层保存；支持「无本地文件」的纯在线影片 | 只存链接也能入库、能播、能统计 | 一期 / 二期 |
| 不重造轮子，借鉴并 fork 现有插件 | 以 MIT 项目为骨架、借鉴成熟开源项目的协议与状态机；只借鉴设计，不复制 AGPL 源码 | 起步快、许可证干净、后续可独立演进 | 一期 |
| 一部影片的资源抽象，来自各途径 | `movies`（作品）← 多个 `movie_sources`（本地 / 在线 / 网盘 / 站点页）＋ `movie_external_ids`（外部 ID） | 一部影片一张卡，下面挂多个来源 | 二期 |
| 多个网站的 URL 指向同一影片要能识别、统一管理 | 四层身份证据（番号 > 站内 ID > 规范 URL > 人工）+ 数据库唯一约束 + 别名表；主源可切换、失效自动降级 | 同一部片不会重复建卡；来源集中查看、启用/禁用、设为主源 | 二期 |
| 完整 URL 还是只存 m3u8？验证与过期怎么办 | 页面 URL 作稳定身份与续期入口，完整播放 URL 作可失效派生产物；m3u8 只是来源类型之一，AVM 已有播放链路 | 链接能验证、标记过期、一键重新获取；带签名的地址不回显 | 二期 |

## 3. 用户能得到的

- **收藏**：任意受支持页面上「加入片库」，可批量；库中已有则显示「已收藏（来自 X 站）」并只追加来源。
- **统一管理**：详情页「来源」区列出全部来源，显示站点、类型、可用状态、验证时间；可设主源、停用、跳转源站、手动添加、重新获取。
- **播放**：主源优先，失效自动降级到下一可用来源；m3u8 与直链都能播，防盗链可走服务端代理。
- **观看数据**：在线观看的时长、进度、分段、完成状态进入现有统计；口味画像、年度回顾、排行榜、续看无需另做一套。
- **偏好分析**：在线观看与本地观看合并统计，可区分来源维度（远期）。
- **隐私与控制**：数据只存本地；插件用最小权限专用令牌，可随时停用/撤销；采集可关闭；页面只显示域名与类型，不回显带签名的完整地址。

## 4. 典型流程

1. 在本机设置页启用「浏览器接入」，生成一次显示的配对信息（地址 + 专用令牌）。
2. 在影片页面点「加入片库」；已收藏过的显示状态和已看时长，不会重复建片。
3. 正常观看；脚本按 10 秒心跳上报，断网期间排队、联网后补报。回到 AVM 即可在详情页、统计页、年度回顾里看到这条观看记录。

## 5. 明确不做（边界）

- 不代抓、不代下、不分发媒体内容，不提供公共云服务或账号体系；沿用单用户、本地优先。
- 不绕过付费或 DRM 保护；加密流（DRM / SAMPLE-AES）标记为不支持。
- 不替换现有本地扫描建库方式，不重写统计体系，不改动既有鉴权强度。
- 不把带签名的播放地址当作长期身份，也不在界面、日志、导出中回显。

## 6.3 播放链路闭环（2026-11-08，实际使用反馈后补齐）

一期 / 二期上线后实测发现：先收藏页面（还没播放）时拿不到播放地址，影片能查询、能刮削，但详情页播放按钮一直是灰的；播放后再点「加入片库」也未必补得上地址。本轮把这条链路补完。

| 问题 | 修复 |
|---|---|
| 脚本抓不到 m3u8 / 直链（blob:、无后缀 playlist、iframe、XHR 内部地址） | 脚本改为 `document-start` 注入，包裹 `fetch` / `XMLHttpRequest.open` 捕获候选；允许子帧运行并通过 GM 存储共享；面板列出候选、支持手动选择 / 粘贴播放地址；同时上报 `site_id` 提升跨站归一 |
| 重复 `link` 用空 `play_url` 覆盖已入库地址，并重置验证结果与有效期 | 只有「抓到且变化了」的地址才更新并重新验证；空地址只补元数据；验证任务也只在地址真的变化时触发 |
| 没有播放地址 → 不生成虚拟 `movie_files` → 播放按钮禁用 | `store.movie_play_source` 在没有可播文件时直接回退到可用在线来源；`movie_detail` 返回 `online_playable`，主播放按钮据此启用；「来源」区新增「播放此来源」 |
| 手动补地址后仍是空地址来源当主源 | `add_source` 在现有主源无地址时自动把新来源扶正 |
| 断网心跳丢失、补报重放撞 `watch_sessions.dedupe_key` 唯一约束报 500 | 脚本新增有序本地队列（联网 / 定时重放）；服务端按 `dedupe_key` 幂等复用场次，重复 start 与无 `session_id` 的补报都返回 200 |
| 服务端代拉播放列表被 CDN 403（防盗链） | 播放列表 / 分片 / 验证统一带「影片页面站点」的 Referer 与可配 UA；403 只标待验证、不判死来源，播放前自动恢复主源；设置页可手动覆盖 Referer / UA |
| 通用请求头不够、失败后又把主源判死 | 补齐完整页面 Referer / Origin / UA / Accept / Accept-Language / Sec-Fetch-*，支持 Referer 模式与自定义头（凭据类头过滤）；无备用来源时保留主源待重试，主源标志丢失可自愈扶正；清空自定义头改为整体替换 |
| 会话绑定站点反复播放失败 | 播放失败原因明确指向「回源站观看」，详情页主入口自动切换为「回源站观看」（原在线播放降为普通按钮仍可重试）；串流地址保留作续期探针与候选，`movie_detail.sources` 下发 `needs_site` 与脱敏 `open_url` |
| 观看明细长期为空（播放器在 iframe / 动态插入时采集不到） | 脚本改为广播采集任务（`watch_task`）：顶层与子帧谁有播放器谁计时（认领去重、dedupeKey 全局一致），等待动态插入的播放器，页面关闭前自动收尾上报；明细过滤「外部播放占位」0 秒会话，方式筛选补齐 extension / web |
| 在线/本地资源混杂，无法按资产形态查找 | 影片库侧栏「标记」新增 `online` / `local` 两个派生筛选（基于 `movie_sources` 的 EXISTS 查询，非冗余字段）：登记过在线来源的影片与纯本地影片；混合片归入「在线来源」 |
| 在线来源失效堆积，缺少运维入口 | 维护中心新增「来源体检」页签（`SourceHealthTab.vue` + `GET /api/sources` + `POST /api/sources/batch`）：按状态 / 需回源站 / 过期筛选，异常优先排序，批量验证 / 重新获取 / 启用停用；`needs_site`、`expired` 为派生视图，不落库 |
| 插件加入的影片没有元数据，还要手动刮 | `ingest.link` 新建影片后自动入队刮削（`scraper.queue_movie_scrape`，受 `ingest.auto_scrape` 控制）；已有任务在跑时挂待补队列、任务结束后补跑，避免连续加入被单任务锁丢掉；追加来源不重复刮削 |
| 自动播放受站点会话限制，入口仍以「播」为主 | 把页面地址当稳定身份：详情页「来源」区顶部固定源站入口（`page_label` = 站点 + 路径，可直接打开），卡片里 `page_path` 拼在站点名后、播放地址单独标记；`playable` 为派生字段，主源不可播但有页面时主按钮切「回源站观看」 |
| 上游需要代理才能访问（国内网络环境） | `app/proxy.py` 统一出口：全局 `network.proxy` 供刮削 / 封面 / 字幕 / 播放 / 验证 / 更新 / AI / 搜索共用；`proxies_for(url, override)` 对 127.0.0.1、局域网、`.local` 强制直连；数据源 `proxy` 与 `stream.upstream_proxy` 作为覆盖；`stream.strm_proxy` 控制普通直链是否中转 |

**403 的边界**：若上游返回 HTML 挑战页，说明校验的是浏览器会话 Cookie / JS 挑战 / 签名绑定，而不只是请求头。按第 5 节边界不代抓、不携带登录态、不绕过付费或 DRM；这种来源只能跳回源站观看，或由用户在「重新获取」里换一个可直连的地址。

**端到端验收**（隔离实例 + 真实浏览器 + 模拟站点）：脚本从 `fetch` 捕获 `master.m3u8?token=…` 并上报 `site_id=12345`；后端生成虚拟记录，`stream-info` 返回 `hls=true + source_id`，`strm/hls` 不再 404；详情页「在线播放」按钮启用、来源区「播放此来源」可见；断开观看事件上报后队列重放全部 200，`watch_sessions` 仅 1 场。真实站点播放仍需用户实测。

## 7. 请审核的决策点

## 8. 设计原则（行业成熟实践）

| 原则 | 具体做法 | 参考的成熟系统 |
|---|---|---|
| **逻辑作品 / 物理来源分离** | `movies` 是作品；文件、链接、网盘、站点页都是挂在其下的来源 1:N | Stash `Scene + files[] + urls[]`；Jellyfin `MediaSources[]`；Radarr `Movie + Releases[]` |
| **稳定身份 / 易失资源分离** | 页面 URL 与番号做身份；带签名的播放 URL 只作派生产物；别名表把历史键指向当前作品 | Stash `stash_ids[]`；Jellyfin `ProviderIds{}`；Peach 番号联合校验 |
| **契约驱动、核心与插件解耦** | 版本化事件契约 + 能力协商；服务端只下发本地站点规则快照，运行时不加载远程代码 | Web Scrobbler Webhook API；Peach 配对令牌与规则快照 |
| **幂等、事件化、离线优先** | `dedupe_key`、事件 envelope、永远返回 200、本地队列补报、重复点击返回同一任务 | Web Scrobbler；bilibili-history-wxt；Peach 五阶段状态机 |
| **最小采集、最小权限、本地优先** | 只采观看必需字段；专用令牌仅允许受限写操作；可关闭、可撤销；脱敏展示 | AVM `docs/安全与隐私设计.md`；Peach 专用令牌（服务端只存哈希） |
| **可观测、可回滚、人工兜底** | 验证状态、来源健康度、合并日志、归档留痕；低置信度必须人工确认 | Peach 状态机 / 错误上报；AVM `history_archive`、`archive_movies` |
| **渐进增强、不锁死** | `kind` 枚举 + provider 注册表 + `schema_version`；先立契约再扩能力；明确「不做」清单 | 上述全部 |

## 11. 数据模型

### `movie_sources`（新）

| 字段 | 说明 |
|---|---|
| `id`, `movie_id` | 外键 `ON DELETE CASCADE` |
| `kind` | `page` / `hls` / `progressive` / `cloud` / `site_page` / `local`（可扩展枚举） |
| `site`, `site_id` | 站点标识与站内 ID（身份证据 L2） |
| `page_url`, `url_canonical` | 稳定页面地址、规范化 URL（去追踪参数，白名单保留作品标识参数） |
| `play_url` | **完整播放地址**（含签名/查询参数，volatile，展示脱敏） |
| `is_primary`, `priority`, `available`, `status` | 主源、优先级、可用性、状态（`valid`/`stale`/`invalid`/`unsupported`） |
| `fetched_at`, `expires_at`, `last_checked`, `refresh_from` | 来源时间与续期入口 |
| `confidence`, `evidence`, `created_at` | 归并置信度与证据 |

唯一约束：`UNIQUE(url_canonical)`、`UNIQUE(site, site_id)` —— 从数据库层保证「同一 URL / 同一站内 ID 不可能挂到两部影片」。

### 其他新表 / 新列

- `movie_external_ids`：`(site, site_id)` → `movie_id`，`UNIQUE`，供插件幂等匹配。
- `movie_aliases`：曾用 `key` / 番号 / 规范 URL → `canonical_movie_id`，`UNIQUE`。**这是归并的灵魂**：合并后旧键仍指向新影片，避免「刚合并完，再上报一次又建出一部」，同时绕开 `movies.key` UNIQUE 不可变的问题。
- `movie_merge_log` / `source_events`：合并与来源变更审计，支持追溯与撤销。
- `movie_files.kind`：标记「虚拟在线记录」，供缺失检测跳过。
- `watch_sessions` 增列：`source_ref`、`device_id`、`dedupe_key`（唯一索引），防止本地播放器与插件、多设备重复计时。

**观看数据挂在作品上，不挂在文件或来源上**：换源、链接失效、删除文件、从本地转在线，统计都不丢。这是 Stash `play_duration/play_history`、Jellyfin 播放状态与 AVM `history_archive` 的共同模式。

## 12. 接口契约

事件 envelope（借鉴 Web Scrobbler Webhook API，音乐语义改为影片语义）：

```json
{
  "schema_version": 1,
  "event": "start | heartbeat | pause | end",
  "time": 1730000000000,
  "dedupe_key": "device:site:pageId:sessionStart",
  "movie": { "code": "…", "site": "…", "site_id": "…", "title": "…", "url": "…" },
  "player": { "position": 123.4, "duration": 3600, "playing": true,
              "watched_sec": 118.2, "segments": [[0, 60], [70, 128]] }
}
```

| 端点 | 用途 |
|---|---|
| `GET /api/ingest/match?code=…` | 判断「库中已有 / 待加入 / 需人工确认」，供插件浮卡 |
| `POST /api/ingest/link` | 幂等建片或追加来源（不新建重复影片） |
| `POST /api/ingest/events` | 观看事件 → `start_session/update_session/end_session` + `set_watch_progress` |
| `GET/POST/PUT/DELETE /api/movies/{id}/sources` | 来源增删改查、设主源 |
| `GET /api/sources/{id}/check`、`POST /api/sources/{id}/refresh` | 验证与续期 |
| `POST /api/movies/{id}/merge` | 人工合并（三期，需确认、可追溯） |
| `GET /api/ingest/capabilities` | 能力协商（`schema_version`、支持的 `kind`、规则版本） |

约定：

- `POST /api/ingest/link` 的 `status` 三态：`created`（新建作品）/ `source_added`（同番号已存在，本次作为**新来源**挂到已有作品，`source_count` 为该作品当前来源数）/ `duplicate`（同一条来源，命中规范 URL 或 `site`+`site_id`，不重复插入；播放地址有更新时 `play_url_updated=true`）。唯一索引冲突（`idx_ms_url` / `idx_ms_site`）落回 `duplicate`，不抛 500。
- 前缀统一 `/api`，子路由不带前缀（由 `app/api.py:41` 继承），跨域导入用 `from ..`。
- **永远返回 200**（业务结果放 body），失败由插件落本地队列补报；错误用 `HTTPException(400/404/502, 中文可读原因)`。
- 鉴权复用现有事务 API Key（`Authorization: Bearer` / `X-API-Key`，写需 `scope=full`）或新增最小权限专用令牌（只存哈希、可撤销）；**不放宽鉴权中间件**。
- 携带 `schema_version`，服务端能力协商后优雅降级；旧插件不会因新字段失效。
- 跨域：MV3 background + `host_permissions` 或 `GM_xmlhttpRequest` 可绕开页面 CORS；若从 content script 用页面 `fetch`，需补 `server.cors_origins` 设置页与四语言文案，并修复 `OPTIONS` 预检被 `AccessTokenMiddleware` 先判 401 的中间件顺序问题。

## 13. 关键机制

### 13.1 身份识别与冲突裁决

| 层 | 证据 | 匹配 | 置信度 |
|---|---|---|---|
| L1 | 番号（`extract_code` 从标题 / URL / 站点字段） | `code_norm` → `movies` / `movie_aliases` | 最高 |
| L2 | `(site, site_id)` | `movie_external_ids` | 高 |
| L3 | `url_canonical` 哈希 | `movie_sources` 唯一约束 | 高 |
| L4 | 标题 + 发行日 + 时长 + 封面相似度 | 仅给候选，**必须人工确认** | 低 |
| L5 | 用户手动「合并到…」 | 兜底 | — |

页面出现两个不同番号，或 L1 与 L2 指向不同影片时，**停止自动归并并返回 `needs_review`**（借鉴 Peach 的身份冲突处理）。镜像域名单独登记，不靠域名相似度自动认作同一站。

### 13.2 多来源统一管理

- 主源选择：用户指定 > 可用性探测 > `priority`；`store.movie_play_source` 从 `LIMIT 1` 改为查主源，过滤 `available`/`stale`。
- 详情页「来源」区扩自 `DetailDrawer.vue` 的「文件」tab 与已有 `hostOf(strm_url)` 展示位；合并确认弹窗参考 `ActressDetailView.vue:157-180`。
- 删除单一来源不影响影片、观看记录与统计；同一番号不同版本 / 分卷作为多来源挂在同一部影片下，不另建片。
- 插件命中时显示「库中已有（来自 X 站），已看 N 分钟」，只追加来源。

### 13.3 URL 存储策略

| 层 | 稳定性 | 是否落库 | 用途 |
|---|---|---|---|
| `page_url` 页面地址 | 长期 | 是 | 身份 + 续期入口 |
| `play_url` 完整播放地址（m3u8 / mp4） | 分钟~小时 | 是（volatile + 脱敏） | 播放 |
| 分片 URL | 播放期 | 否 | 由 `_rewrite_playlist` 实时解析 |

**不能只存 m3u8**：签名过期后变死链且无法续期；**不能只存页面 URL**：每次播放现场解析，慢且受站点改版影响。「完整 URL」是值，「m3u8」是类型，两者都存、各司其职。

### 13.4 播放

AVM **已完整支持 m3u8**，无需重建：

- `.strm` 一行地址 → `movie_files.strm_url`；三条播放路径见 `app/api.py:3252-3256`。
- HLS：`GET /api/strm/hls/{id}` 拉 playlist → `_rewrite_playlist`（`app/api.py:3355-3371`）用 `urljoin` 改写分片 / `#EXT-X-KEY` 密钥 / `#EXT-X-MAP` init 段 / 子 playlist → `/api/strm/seg/{id}/{name}?t=…` → 前端 video.js/VHS。
- 防盗链 `_strm_headers`（可配 UA / Referer）、Range 透传、Content-Type 归一、一次性分片 token（`_STRM_TTL=600`，防开放代理）、`Cache-Control: no-store`、直播 `Infinity` 时长处理均已具备。
- 直链：302 直连，或 `strm_proxy` 服务端代理。

需补三点：

- `_is_hls()`（`app/api.py:3269-3270`）目前**只看 `.m3u8` 后缀**，无后缀带查询参数的 playlist 会被误判成直链 → 改为按内容（首行 `#EXTM3U`）判定，后缀兜底；
- **纯在线影片没有磁盘文件，`os.path.exists(path)` 类硬门槛会拦住播放**：`app/api.py:229`（`POST /movies/{id}/play` 外部播放）、`:3430`（`GET /stream/{id}` 直链 mp4）、`:3462`（`playback-info`）、`:3501`（`prepare-stream`）共 4 处。现有 `.strm` 是磁盘上的真文件故能通过，虚拟记录必然 404，表现为「列表里看得到、点开播不了」。修法：先判 `strm_url`，有值则跳过路径存在性检查（HLS 走 `/api/strm/hls/{id}`，不查路径，不受影响）；
- DRM / `SAMPLE-AES` 明确标记不支持。

### 13.5 验证与过期

**三级验证**（不下载整段视频、不用 `HEAD`，CDN 常拒绝）：

1. 入库轻验证：`GET` playlist（超时 `(8,20)`、限响应体、只 http/https、禁内网与任意重定向，SSRF 边界照 `app/routers/subtitles.py:24-35`）→ 首行 `#EXTM3U` → 区分 master（`#EXT-X-STREAM-INF`）/ media（`#EXTINF`）→ 相对 URI 可 `urljoin` → 抽查 1~2 分片（`Range: bytes=0-1023`，期望 200/206 且非 `text/html`）→ 累加 `#EXTINF` 得时长 → `#EXT-X-ENDLIST` 判断 VOD/直播。
2. 播放前：`stream-info` 读缓存的 `status`/`expires_at`，过期先 refresh 再返回。
3. 播放中：VHS/hls.js 的 403/410/HTML 错误 → 触发一次 refresh → 重建 playlist → 限时重试。

验证失败只标 `available=0` + 原因，**不自动删除来源**（AGENTS.md 删除类操作需确认）。

**三种过期源**：源站签名参数（`expires`/`e`/`X-Amz-Expires`/token TTL）、分片独立签名（长片播放中途 403，必须整体刷新 playlist 重新改写）、AVM 自己的分片 token（600 秒，长片会先报「分片地址已失效，请重新播放」）。

**续期闭环**：`page_url` → 站点规则重新提取 `play_url` → 更新 `fetched_at`/`expires_at`/`status` → 重放；解析不出有效期则用保守 TTL + `fetched_at` 标 `stale`。秒级 IO，走 `submit_task()`。连续失败自动降级到下一可用来源。防盗链过期常表现为返回 HTML 登录页而非 403，验证须检查内容而非只看状态码。

### 13.6 观看数据与去重

事件转调 `store.start_session/update_session/end_session`（`app/store.py:775-797`）与 `set_watch_progress`；`method` 用新值 `extension`（TEXT 自由列）。只累计真实播放（暂停 / 缓冲 / seek 不计，阈值可配）、10 秒心跳、离线队列、`dedupe_key` 幂等补报，防止与 `app/monitor.py` 的本地播放器监控重复计时。**统计页面零改动**。

### 13.7 合并两部影片（三期）

自动识别做对后，合并只用于历史重复数据与人工纠错。必须单事务，且**不能复用 `store.delete_movie`**（`app/store.py:1533-1541`，FK CASCADE 会清掉 `watch_progress`/`watch_sessions` 且无快照）。

- CASCADE 表 11 张：`movie_files`、`movie_actress`、`movie_genre`、`movie_tag`、`watch_progress`、`collection_items`、`collection_playhead`、`watch_sessions`、`movie_previews`、`movie_subtitles`、`ad_checks`。其中 `watch_progress.movie_id` 是主键、`movie_previews`/`ad_checks` 是主键、`collection_items` 是复合主键 → 需 `INSERT OR IGNORE` + 聚合（进度取较大、会话按 `dedupe_key` 去重），不能裸 `UPDATE`。

### 14.2 缺口

1. **无 `POST /movies`**：全仓唯一 `INSERT INTO movies` 在 `app/store.py:233`，只能靠本地扫描入库。
2. **URL 不是一等资源**：`movie_files.strm_url` 必须依附磁盘 `.strm` 文件；`store.movie_play_source`（`:809-821`）用 `LIMIT 1` 只取一条；`.strm` URL 完全不参与身份计算。
3. **无外部 ID / 多来源映射表**：`scrape_source` 只是字符串，MetaTube 的 `provider+id` 抓取期用完即丢。
4. **`movies.key` 事实上不可变**：人工补番号（`app/store.py:1409-1414`）与存量重解析（`:3305-3309`）都不重算 key，按 URL 建的 `NC:<sha1(路径)>` 影片后来刮出番号也不会与同番号片归并；`upsert_scanned_file` 的 INSERT 无 `ON CONFLICT` 兜底（`:231-243`）。
5. **观看会话缺来源 / 设备 / 去重维度**：多端或本地播放器 + 插件会重复计时。
6. **无「合并两部影片」能力**：`app/dedupe.py:59-87` 只把重复文件标 `missing`；全仓 `merge_movies` 零结果。
7. **入库不验证**：`app/scanner.py:72-90` 只校验 `http(s)` 前缀；`_is_hls` 只看后缀；无 `expires_at`/`last_checked`/`status`，403 只抛 502，不刷新不降级。
8. **跨源接入**：`server.cors_origins` 默认空且缺设置页 UI 与四语言文案；`CORSMiddleware` 在最内层，`OPTIONS` 预检会先被 `AccessTokenMiddleware` 判 401。
9. **前端与文档**：`DetailDrawer` 无可编辑 URL 项；`docs/安全与隐私设计.md:37` 目前把「恶意浏览器扩展」排除在威胁模型外，引入官方插件后需补章节。
10. `movie_files` 在 `app/` 下 12 个文件、约 85 处引用（`app/store.py` 占 43 处）；真正会因「无本地文件」出错的仅 `playable_cnt`（`:499-500`、`:2565-2569`、`:2769`、`:3187-3191`）、缺失检测（`:354-463`）、聚合（`:309-337`）、扫描 diff（`app/scanner.py:146-175`）约 8~10 处。
11. **「纯在线影片能否像本地影片一样」的隐藏门槛**：列表 / 搜索 / 详情 / 评分 / 标签 / 片单 / 导出 / 统计全部基于 `movies` 表，虚拟记录让 `playable_cnt > 0` 后即与本地片一致（`app/store.py:500`、`:718`）；但 `app/api.py:229` / `:3430` / `:3462` / `:3501` 的 `os.path.exists` 会让直链播放、播放兼容信息与外部播放 404。此外 `app/api.py:3118-3119` / `:3157-3158` 对串流明确「不支持预览图」，`app/api.py:2439-2440` 排除串流的 sidecar 字幕，`monitor.start_external_monitor`（`app/api.py:258-259`）依赖本地路径与 PID —— **在线观看时长必须由插件上报，不会自动产生**。番号为空时 `display_code` 为空（`app/store.py:1354`），搜索只能靠标题，因此插件需尽量抓番号 / 标题或支持人工补填。

| **Stash**（Go，AGPL-3.0，约 13k★） | `Scene` 逻辑作品：`files: [VideoFile!]!` + `primary_file_id`、`urls: [String!]!`（外链，旧的 `url` 已废弃）、`stash_ids: [StashID!]!`（`endpoint` + `stash_id`）、`play_duration`/`play_count`/`play_history`/`resume_time` | **最完整的参考**：作品 / 文件 / 外链 / 外部 ID / 观看数据五层分离。注意 `urls[]` 是资料页而非播放源；AVM 的 `watch_sessions` 比它的观看记录更细 |

| **Radarr / Whisparr**（GPL-3.0） | `Movie`（逻辑）+ `MovieFile`（落地）+ `Releases[]`（未获取的多来源候选，含 indexer / quality / protocol / size） | 「还没下载的链接」也能作为候选挂在影片下，对应「云盘 URL 当收藏」 |
| **Peach**（Python，AGPL-3.0-or-later，约 13k★，2026 新项目） | 本地盘 / SMB / 挂载网盘 / 在线媒体库统一成一座馆藏；同一番号不同版本与分卷合成一张卡；资源搜索走 Prowlarr / Jackett 的 Torznab；云下载渠道 + 入库后处理；观看记录与偏好分析存本地 | 与 AVM 几乎同构的产品对标，「媒体来源 + 渠道 + 站点脚本」三层值得参考；**AGPL** |
| **CloudSaver**（Vue3 + Express + SQLite） | 多源资源搜索 + 网盘一键转存 | 只是「来源发现 / 转存」，不是馆藏模型；MIT |

**提炼的通用模型**：`Movie`（逻辑作品，番号为身份）→ `Sources[]`（1:N，多途径）→ `ExternalIds[]`（多站映射）→ `WatchSessions`（挂作品，与来源解耦）。AVM 的 `movies` + `movie_files` 已经等价于 Stash 的 `Scene + files[]`，因此**不需要「抄 Stash」，只需补 `urls[]` 与 `stash_ids[]` 两个 1:N 关系**。

## 17. 许可证合规结论（重要）

- AVM 主体是 **MIT**（`README.md:25`、`:329`）。
- **Peach、Peach Userscript、Stash 均为 AGPL-3.0(-or-later)**，Radarr/Whisparr 为 GPL-3.0，Jellyfin 为 GPL 系。**不得把其源码复制进 AVM 主体**。
- 可行做法：只借鉴接口契约、数据模型与流程（思想不受著作权保护）；插件用 MIT 项目或自研；若确要 fork AGPL 插件，放独立仓库、独立分发、仅通过 HTTP API 通信并履行 AGPL 开源义务（正式发布前建议法务确认）。
- 已核实 MIT：`web-scrobbler`、`bilibili-history-wxt`、`stash-checker`、`CloudSaver`。未核实：VideoTracker、Where Was I、stasharr 的许可证。
- 检索到的 star 数与版本为 2026-11-07 快照，后续可能变化。

## 18. 讨论演进摘要

1. **需求提出**：在线观看的影片、观看时长、云盘 / 视频链接收藏都要进 AVM；借鉴现有插件 fork 打通；调研「影片资源抽象」的开源实现。
2. **第一轮结论**：AVM 的观看数据与偏好分析体系已完整，缺的只是「URL 作为一等资源」与「外部上报通道」；不是造新系统，是接一根管子 + 一张来源表。给出可借鉴插件清单与 Stash/Jellyfin/Radarr/Peach/CloudSaver 模型对比，以及分阶段方案与许可证风险。
3. **改造量评估**：`movie_files` 约 85 处引用看似吓人，但真正会因「无本地文件」出错的仅 8~10 处；提出「复用 `.strm` 语义插一条虚拟 `movie_files` 记录」的便宜走法，让详情页、统计、前端几乎零改动（后经第 7 条复核，播放链路仍需补 4 处路径判断）。分 A/B/C 三档，推荐 B 档。
4. **多 URL 归一**：提出四层身份证据 + 数据库唯一约束 + `movie_aliases` 别名表；指出「先防后治」——识别做对后 90% 场景不需要合并；揭示 `movies.key` 不可变导致的分裂风险与 `merge_movies` 缺失，列出 16 张表的迁移清单与 `delete_movie` 陷阱。
5. **播放 URL / m3u8**：确认 AVM 已完整支持 HLS（含子 playlist、AES-128 密钥、防盗链、Range、一次性分片 token）；确定「页面 URL 作身份 + 完整播放 URL 作易失派生产物」的三层存储策略；补验证三级、三种过期源与续期闭环；明确带签名 URL 属凭据须脱敏、DRM 不支持。
6. **落文档**：汇总为待审核文档 `docs/浏览器插件与在线资源设计.md`，同步 `AGENTS.md` 文档索引。
7. **一等公民确认**：复核「网页加入的影片是否也在影片库、能像本地片一样搜索查询观看」。结论：列表 / 搜索 / 详情 / 评分 / 标签 / 片单 / 导出 / 统计都基于 `movies` 表，虚拟记录使 `playable_cnt > 0` 后即一致；HLS 链路不查本地路径可直接播；但 `app/api.py:229` / `:3430` / `:3462` / `:3501` 四处 `os.path.exists` 会让直链播放、播放兼容信息与外部播放 404，必须补进 B 档清单。另确认合理差异：串流不支持本地抽帧预览、sidecar 字幕与重封装；在线观看时长必须由插件上报而非本地播放器监控产生；无番号片搜索只能靠标题。
8. **GitHub 插件生态补充调研**：新增 `JAV-JHS 3.3.6`(MIT)、`JavDB Power Tools`(MIT)、`JavdBviewed`(AGPL)、`javranking-extension`(MIT)、Stash 的 URL scraper / Tagger / 指纹去重、MetaTube/AMMDS/JavSP、Yamtrack/Bangumi-syncer 等项目；逐项对照 AVM 代码后，筛出 P0 五项（黑名单排除过滤、JSON 全量导入导出、插件三态标记、Webhook 出站、批量刮削人工确认）、P1 八项、P2 三项，并明确「免 VIP / 破解限制 / 磁力与云下载 / 运行时远程代码 / AGPL 源码复制」不借鉴。详见第 15.1 节，候选功能**尚未纳入待审核设计**，等第 7 节第 9 点勾选。

# 第四部分 · 改造量、验收与风险

## 19. 改造量分档

| 档位 | 内容 | 量级 | 建议 |
|---|---|---|---|
| **A** | 只加 `movie_sources` + `movie_external_ids` 两张表，URL 仅作收藏 / 元数据 | 小，新增为主，4~6 文件、<10 处 | 不够，还不能播 |
| **B** | A + 虚拟 `movie_files` 记录，让「仅在线影片」可建、可播、可统计 | **中等偏小**，8~10 文件、25~40 处，多数是加一个 WHERE 条件 | ✅ 推荐 |
| **C** | 完全照搬 Stash：Scene/Movie/Group 分层、联邦 ID、指纹去重、merge 语义 | **大**，等于重写 `store.py` 全部列表 SQL + 所有前端页面 + 历史数据迁移 | ❌ 不建议 |

**B 档便宜走法**：给纯在线影片在 `movie_files` 写一条 `path` 为伪路径、`strm_url` 为真实 URL、`size=0`、`missing=0` 的虚拟记录，`playable_cnt` 自动成立，`movie_play_source` 直接返回播放地址。必须改的仅：

1. `app/store.py:398-463` `check_missing_files` 跳过虚拟记录 —— **最大坑**，否则 `os.path.exists` 会标 `missing` 并触发 `_delete_empty_movies` 删片；
2. `app/scanner.py:146-175` / `:266` 与 `app/store.py:354-395` 扫描 diff 忽略虚拟记录（`app/scanner.py:457` 已有 `COALESCE(f.strm_url,'')=''` 先例）；
3. `app/store.py:309-337` `refresh_aggregate` 的 `file_count` 排除在线源；
4. `app/store.py:220-306` 新增独立 `upsert_online_source()`，不复用扫描入口；
5. `app/api.py:229` / `:3430` / `:3462` / `:3501` 四处 `os.path.exists` 改为「有 `strm_url` 则跳过」—— 这是「网页加入的影片能像本地片一样观看」的**必要条件**，漏了就会「列表里看得到、点开播不了」；
6. `app/db.py` 迁移段新增表 / 列，幂等。

**幂等 key 是正确性关键**：纯在线影片常无番号，必须在 `app/store.py:220-306` 定死稳定 key 规则（`site:site_id` 或 `url_sha1`），否则插件重复上报会建出重复影片。

## 20. 验收

按 `AGENTS.md` 第 6 节四道闸：

1. `python -m compileall -q app`（前端 `npm run build`）；
2. `python -c "from app.main import app"` 干跑导入；
3. 重启 + 用 `data/access_token.txt` 令牌冒烟真实接口（**含一次真实 `OPTIONS` 预检**）；
4. 前端构建 + 浏览器目视点一遍改动路径。

本特性额外回归项：

- 跑一次「检查缺失」后，在线影片**不被标 missing、不被删除**；
- `playable_cnt > 0`，列表 / 筛选能正常找出纯在线影片；
- `watch_sessions` 能写入且口味画像数值变化；重复上报不产生重复会话；
- 迁移重复执行不报错；`app.openapi()['paths']` 与改前比对 **0 缺失**；
- m3u8 与直链各播一次；403/410 触发 refresh 与降级；带签名 URL 不出现在界面 / 日志 / 导出中。

## 21. 风险与待办

| 风险 | 处理 |
|---|---|
| AGPL 代码并入 MIT 主体 | 只借鉴设计；插件独立仓库 + MIT / 自研；必要时法务确认 |
| 带签名播放 URL 属临时凭据 | 展示只给 host + 类型；`GET /config`、日志、导出、诊断包、插件错误上报全部脱敏；不回显令牌 |
| SSRF / 开放代理 | 验证请求只 http/https、禁内网、限超时与体积、不跟随任意重定向；沿用 `_STRM_SEG` 一次性 token |
| 重复计时 | `dedupe_key` + 时间窗合并，与 `app/monitor.py` 协调 |
| 误合并、误删 | 低置信度必须人工确认；合并需确认且可追溯；删类操作有确认；不用 `delete_movie` 删源片 |
| 威胁模型过期 | `docs/安全与隐私设计.md:37` 需补「官方浏览器插件」章节（令牌权限、规则来源、字段脱敏、可关闭 / 撤销） |
| 站点规则维护成本 | 规则数据驱动 + 本地快照下发 + 版本化；不硬编码站点逻辑，运行时不拉远程代码 |
| DRM / 付费内容 | 明确不支持，验证阶段标记 `unsupported` |
| 并发上报主键冲突 | 先查别名表 + `INSERT ... ON CONFLICT DO NOTHING`（现 `app/store.py:231-243` 无兜底） |

**待核实 / 待决**：VideoTracker、Where Was I、stasharr 的许可证；`schema_version` 具体起始值；站点规则白名单范围；第一部分第 7 节的 8 个审核决策点。
