# AV 影片管理 / 番号刮削器 · 开发文档

> 面向后续 AI / 开发者，用于快速理解架构并继续开发。
> 生成于 2026-08-02，基于当前代码快照（FastAPI + SQLite + Vue3/Vite）。

---

## 0. 一句话架构

**本地影视库管理 + 番号刮削器**：后端 FastAPI 负责扫描磁盘、解析番号、抓取元数据、提供 REST API；前端 Vue3（Vite）作为单页 GUI；数据存本地 SQLite；封面/头像/预览图落本地目录。无账号、无云端，所有数据在 `data/`。

## 2. 运行与构建

### 2.1 开发模式（前后端分离）

```bash
# 终端 1：启动后端（默认 8770）
python run.py serve
# 等同：uvicorn app.main:app --host 127.0.0.1 --port 8770 --reload

# 终端 2：启动前端 dev server（默认 5173，代理 /api → 8770）
cd web_src
npm install
npm run dev
# 浏览器打开 http://localhost:5173
```

### 2.2 构建前端到 web_dist

```bash
cd web_src
npm install
npm run build    # 产物输出到 ../web_dist
```

### 2.3 生产 / 打包

```bash
python run.py serve          # 源码模式直接托管 web_dist
python run.py build          # 调用 build.py 生成单目录打包
python run.py pack <ver>     # 生成带版本号的发布包
```

打包脚本 `build.py` 关键点（已含 AI 支持）：
- `--collect-submodules app` → 递归收集 `app/`（含 `providers/`、`ai.py`）。
- `--add-data "web_dist;web_dist"` → 把前端构建产物冻结进 exe。
- 一系列 `--hidden-import` → uvicorn / multipart / email / charset_normalizer 等。
- `app/ai.py` 依赖 `requests`（已在 requirements.txt），无需额外打包参数。

> **修改前端后务必 `npm run build`**，否则 `web_dist` 不更新、服务仍托管旧产物。改完后端/前端后，浏览器**硬刷新**（`Ctrl+Shift+R`）以避开缓存。

## 3. 后端核心模块

### 3.1 配置 (`app/config.py`)

- 配置存 `data/config.json`，与 `DEFAULT_CONFIG` 深合并（`_deep_merge`）。
- 目录常量：`DATA_DIR`、`COVER_DIR`、`avatar_dir`、`WEB_DIR`（= `web_dist`）。
- 配置段：
  - `scan_dirs`：扫描根目录列表。
  - `scraper`：`enabled_providers`、代理 `proxy`、CF Cookie、并发等；
    - `chrome_debug_port`（默认 9222）：avwiki 经 CDP 抓取时连接的本机 Chrome 调试端口；后端会在需要时**自动拉起一个独立的无窗口 Chrome**（profile 存于 `data/chrome_profile`），无需用户手动启动。
  - `ffmpeg_path`：预览图抽帧用。
  - `ai`：`enabled` / `base_url` / `api_key` / `model` / `temperature`（见 §6）。

### 3.2 番号解析 (`app/parser.py`)

- `extract_code(text) -> (code, raw, rule)`：
  - `code` 为格式化番号（如 `IRO-061`）；未识别返回 `(None, '', '')`。
  - **注意返回是 3 元组**，调用方需 `parsed[0]` 取 code，勿写成 `code, rule = extract_code(...)`（会报错）。
- 规则 `_CODE_RULES`：FC2、STANDARD、MARKET 等。STANDARD 已支持「字母紧贴数字 + 尾随版本字母」：`IRO061C → IRO-061`、`SONE 760CH → SONE-760`。
- 其他：`detect_flags`（字幕/无码/流出/4K/VR 等布尔标记）、`detect_resolution`、`detect_part`（分片 cd1/cd2）、`parse_file(path)`（返回归并所需的完整 dict：`key/code/has_code/code_rule/title/part/resolution/folder/filename/ext`）。
- `key` 规则：有番号 → `code.upper()`；无番号 → `NC:<sha1(路径)[:12]>`（按内容去重）。

### 3.3 数据访问 (`app/store.py`)

**这是后端最重要的文件，所有 SQL 都在这里。** 改动数据读写优先在此处理。

关键能力：
- 分类表 `_TAXONOMY = {actresses, genres, studios, series, tags}`，关系表 `_REL_META`（movie_actress / movie_genre / movie_tag）。
- `upsert_scanned_file`：扫描写入，同 key 多版本布尔取并集、分辨率取较高。
- 检索 `search_movies(params)`：支持 `q/actress/genre/tag/studio/series/prefix/year/flags/sort/op/page/page_size`；`SORTS` 与 `FLAG_CLAUSES` 字典定义了可选项。
- `movie_detail`：详情 + 关联文件/女优/类型/标签/观看进度（`LEFT JOIN watch_progress`）。
- 统计/分面：`facets`、`actress_wall`、`stats`、`stats_enhanced`、`rankings`。
- 观看进度：`start_session/update_session/end_session`、`set_watch_progress`、`continue_watching`、`watch_analytics`。
- 片单：`list_collections / create_collection / collection_movies` 等。
- 数据健康：`health_check`（缺失文件/分片不完整/缺封面/占位图/未识别番号/疑似重复）、`reparse_all_codes`（存量重解析番号，仅改 `only_missing=True` 的记录）、`integrity_issues`、`storage_stats`。
- 去重在 `dedupe.py`，劣质片筛查 `scan_quality` 也在 `dedupe.py`：四类（广告样片/低码率压片/同番号劣质版本/损坏不完整），`pick_best` 在同组选最优版保留。`/quality` 端点暴露结果，`/health-check` 暴露六类数据健康体检。

### 3.4 HTTP 路由 (`app/api.py`)

`APIRouter(prefix="/api")`。要点：
- **图片接口一律 `Cache-Control: no-cache`**（`/cover`、`/avatar`、`/fanart`），并带 `ETag` 支持 304。背景：曾因 `max-age=86400` 强缓存导致换封面不生效，已改为 no-cache。
- 远程图片经 `_proxy_image` 代理规避跨域/防盗链。
- 任务类端点（`/scan`、`/scrape`）把耗时操作丢进 `threading.Thread(daemon=True)`，前端轮询 `/scan/status`、`/scrape/status`（`composables/useTasks.js`）。
- AI 端点见 §6。
- 完整端点清单（节选）：`/movies`、`/movies/{id}`、`/cover/{id}`、`/facets`、`/actresses`、`/stats`、`/scan`、`/scrape`、`/reparse-codes`、`/similar`、`/continue-watching`、`/collections`、`/dedup`、`/quality`、`/health-check`、`/ai/*`、`/config`、`/server/check-update`。

#### 3.4.1 检查更新 (`GET /server/check-update?channel=stable`)

版本页「检查更新」按钮调用，返回 `{ latest, download_url, released, notes, update_available, error }`。

- **更新源**：优先读 `config.json` 的 `server.update_feed`（通用版本清单 JSON：`{version, download_url, released, notes, channel}`）；为空时回退 GitHub Releases API（`api.github.com/repos/<repo>/releases/latest`）。
- **墙内网络适配**：
  - 复用 `scraper.proxy`（刮削代理）作为请求代理，规避直连 SSL/EOF 失败。
  - 命中 `api.github.com` 时，候选源按 **镜像优先 → 原始 API 兜底** 顺序轮询：`ghfast.top` / `gh-proxy.com` / `mirror.ghproxy.com` 前缀转发，任一返回含 `tag_name`/`version` 的有效数据即采用。
  - 用 `_valid()` 校验响应：GitHub 限流会返回 `{"message":...}`（HTTP 403），不含版本字段，会被识别为失败并继续尝试下一候选源（原实现曾误判此类响应为成功，已修复）。
- **前端兜底**：若全部候选源失败，`error` 非空，版本页展示红色提示并提供「前往 Releases」按钮，直接跳转 GitHub Releases 页，用户可手动下载。

### 3.5 数据源 (`app/providers/`)

- `base.py`：`Provider` 基类，约定 `fetch(movie) -> meta dict | None` 与 `name/last_error`。
- `http_html.py` / `http_json.py`：带代理/UA/Cookie 的抓取基类。
- `javbus.py` / `javdb.py`：具体站点适配器。
- `avwiki.py`：**av-wiki.net 素人片源**。该站用 LiteSpeed「请稍候…」验证页拦截普通请求，因此 `fetch` 优先走 `cdp_fetch`（见下），失败才回退普通 `http_get`；自身页面无封面，封面由 scraper 回退到 javbus/javdb。
- `local_nfo.py`：优先读本地 `.nfo`（离线友好）。
- `build_providers(cfg)`：按配置启用顺序返回 provider 列表；`describe()` 供设置页展示。

### 3.5.1 CDP 抓取 (`app/cdp_fetch.py`)

av-wiki.net 的反爬是**会话信任**型（新会话会被卡在每 5 秒 reload 的验证页），普通 `requests` + Cookie 复制无效。解决方案：

- `ChromeManager`：**进程级单例**的常驻 Chrome 管理器。首次抓取时自动用固定 `--user-data-dir`（`data/chrome_profile`）拉起一个 `--headless=new` 的 Chrome、打开调试端口（`scraper.chrome_debug_port`，默认 9222）；之后复用同一个 Chrome，不弹窗、完全后台。
- `CDPSession`：基于 `websocket-client` 的轻量 CDP 客户端（`Target.createTarget` → `attachToTarget` → `Page.navigate` → `Runtime.evaluate` 轮询 `document.documentElement.outerHTML`），轮询期间等待验证页自行放行。
- `cdp_fetch(url, port, wait, auto_launch=True)`：便捷函数；`auto_launch=True` 时端口未监听会自动拉起 Chrome。`avwiki.py` 以 `auto_launch=True` 调用，因此**无需用户手动启动 Chrome**，采集任务可全后台自动运行。
- **前置条件**：机器需安装 Chrome（默认探测 `C:\Program Files\Google\Chrome\Application\chrome.exe` 等路径）。未安装或拉起失败时 `cdp_fetch` 返回 `None`，`avwiki.py` 回退普通 `http_get`（可能因反爬失败，但不影响其它源）。

> 为何不用「借用用户日常 Chrome」：会话信任依赖用户日常的浏览上下文，改用程序自管的独立 profile 后，实测该站点对 headless Chrome 同样放行，且可完全后台、不干扰用户。

### 3.5.2 封面补全机制

素人 / 无码片在 javbus 详情页常无封面，抓取层做了三层兜底：

1. **搜索结果回退**：`javbus._parse` 在详情页 `#cover` 为空时，调用 `_search_cover(code)` 从站内搜索结果页（`movie-box` 缩略图，图床为 cloudfront）取封面。
2. **相对路径补全**：`_best_cover` 已覆盖 `/imgs/cover/` 与 `/pics/cover/` 两套 javbus 图床前缀的相对路径，补全为绝对 URL。
3. **Referer 防盗链**：`images.download(url, cfg, referer="")` 支持显式 referer；对 `cloudfront.net` 域名自动带 `https://www.javbus.com/` 防盗链，避免图床 403。

scraper 层 `scrape_one_parallel` 还会在第一个命中源无封面时，用后续源（javbus/javdb）的封面补齐（`primary_meta` 缺 `cover` 则取任一 `meta.cover`）。

## 4. 前端核心模块

### 4.1 入口与布局

- `main.js`：挂载 App + 引入 5 个样式表（顺序：tokens → base → ui → layout → styles）。
- `App.vue`：顶层布局（`TopNav` + `Sidebar` + 动态 `<component :is="VIEWS[state.view]">` + 全局 `DetailDrawer`/`ToastLayer`/`ConfirmDialog`）。
  - **新增视图必须在这里注册**：`import XxxView` 并加入 `VIEWS` 字典。

### 4.2 全局状态 (`state.js`)

- `state = reactive({...})`：视图路由 `view`、查询条件（`q/actress/genre/studio/series/prefix/year/flags/sort/multiOp`）、用户偏好（`theme/density/cardSize/sidebarCollapsed/page_size`）。

- `applyTheme()`：设置 `<html>` 的 `data-theme`/`data-density`，**且必须设置 `el.style.colorScheme`**（否则暗色下原生表单控件文字看不清——这是已修复的坑，新增表单页时注意）。
- 常量导出：`FLAGS`、`FACET_KINDS`、`SORTS`、`NAV_GROUPS`（导航项，新增管理类页面在此加 `{id, label}`）、`NAV_ICONS`。

### 4.3 API 封装 (`api.js`)

- `api(path, options)`：统一 fetch，JSON 自动序列化，非 2xx 抛错（取 `detail`）。
- `get/post/put/del` + 一堆语义化导出（`listMovies`、`getMovie`、`aiStatus` ...）。
- 静态资源地址：`coverUrl(id)`、`avatarUrl(name)`、`fanartUrl(id)`、`streamUrl(id)`、`previewUrl(...)` —— **前端一律走这些接口，不要直接拼文件路径**（远程图需后端代理）。

### 4.4 组件与视图

- `components/`：`TopNav`（搜索框 + 语义搜索开关）、`Sidebar`（主导航，非筛选）、`MovieFilter`（影片库左侧常驻筛选栏：类型/标签/评分/标记始终展开，女优/厂商/系列等长尾维度折叠 + 组内搜索 + 已选置顶）、`DetailDrawer`（详情 + 播放 + AI 按钮）、`MovieCard`（封面 + 续播进度条）、`ToastLayer`、`ConfirmDialog`、`HealthPanel` 等。

## 5. 数据库 schema（概要）

库文件 `data/library.db`。核心表：
- `movies`：id, key, code, has_code, code_rule, title, folder, studio_id, publisher_id, series_id, release_date, runtime, size, file_count, rating, favorite, watched, watchlist, play_count, last_played, cover, cover_source, fanart, plot, scraped_at, subtitle, uncensored, leak, hd4k, vr, resolution, created_at, updated_at, added_at。
- `movie_files`：id, movie_id, path, filename, ext, size, mtime, part, missing, quick_hash。
- `actresses` / `movie_actress`；`genres` / `movie_genre`；`tags` / `movie_tag`；`studios`；`series`。
- `watch_sessions`：movie_id, start_pos, end_pos, watched_sec, finished, segments, method, 时间戳。
- `watch_progress`：movie_id, position, duration, finished（列表页续播进度来源）。
- `collections` / `collection_movies`：片单（manual 手动 / smart 智能按 rule 自动聚合）。
- `scan_logs`：扫描历史。

> 建表 SQL 在 `store.py`（搜索 `CREATE TABLE`）。新增字段时同步更新 `upsert_scanned_file` / `movie_detail` / 导出 CSV 等受影响处。

## 6. AI 增强（可选，非内置模型）

`app/ai.py` 提供兼容 OpenAI 协议的客户端，**不内置任何模型**，需用户自行配置端点。

### 6.1 配置（设置 → AI 增强，存 `config.ai`）

| 字段 | 说明 |
| --- | --- |
| `enabled` | 总开关 |
| `base_url` | `https://api.openai.com/v1` 或本地 `http://127.0.0.1:11434/v1`（Ollama） |
| `api_key` | 云端/中转必填；本地 Ollama 留空 |
| `model` | `gpt-4o-mini` / `deepseek-chat` / `qwen2.5` 等 |
| `temperature` | 0–1，默认 0.4 |

所有请求发往用户配置的端点，密钥只发往该端点，不外传。

### 6.2 能力

- `is_available(cfg)`：配置是否可用。
- `generate_synopsis(movie, cfg)`：依元数据生成/润色中文简介，写回 `movies.plot`。
- `suggest_tags(movie, cfg)`：返回 3–8 个中文标签建议（前端让用户选择追加）。
- `parse_search_intent(query, cfg)`：把自然语言查询解析为结构化筛选条件（genre/actress/studio/series/year/keyword），供语义搜索使用。

### 6.3 端点 + 前端入口

- `GET /ai/status` → `api.js: aiStatus()`
- `POST /ai/generate-synopsis/{id}` → `aiGenerateSynopsis(id)`
- `POST /ai/suggest-tags/{id}` → `aiSuggestTags(id)`
- `POST /ai/search-intent` → `aiSearchIntent(query)`
- 前端入口：`DetailDrawer.vue`（详情页「AI 生成简介 / AI 补充标签」按钮，v-if `aiReady`）；`TopNav.vue`（搜索框「AI」开关，开启走 `aiSearchIntent` 解析后套用 state 筛选，失败降级关键词）。

> **新增 AI 功能时**：在 `ai.py` 加函数 → `api.py` 加端点 → `api.js` 加导出 → 在合适组件调用。保持「兼容 OpenAI 协议」这一约束，勿写死特定厂商 SDK。

## 7. 开发约定与已知坑

1. **番号解析返回 3 元组**：`code, raw, rule = extract_code(...)` 正确；`code, rule = ...` 会解包报错。重解析逻辑见 `store.reparse_all_codes`。
2. **封面不加强缓存**：`/cover` 等必须 `no-cache`，否则换图不生效。前端换封面后提示用户硬刷新。
3. **`color-scheme` 必须随主题切换**，否则暗色表单控件文字不可读（已在 `state.js` 处理）。
4. **前端静态资源走接口**：`coverUrl/avatarUrl/fanartUrl/streamUrl`，不要直接拼路径；远程图经后端 `_proxy_image`。
5. **改前端必须 `npm run build`** 到 `web_dist`，服务托管的是 `web_dist` 而非 `web_src`。
6. **新增视图**：在 `App.vue` 的 `VIEWS` 注册，并在 `state.js` 的 `NAV_GROUPS` 加导航项；若需顶栏入口则同步 `TopNav`。
7. **新增 /api 端点**：放 `app/api.py`，同步在 `web_src/src/api.js` 加语义化导出供组件调用。
8. **SQL 集中**：优先在 `store.py` 写查询，避免散落各模块。
9. **后台任务**：耗时操作丢线程（`api.py` 已有模式），前端用 `useTasks` 轮询状态。
10. **数据隐私**：全部本地，不联网上报；联网仅发生在用户配置的刮削源 / AI 端点。
