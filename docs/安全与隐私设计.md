# 片匣 · 安全与隐私设计

面向 **NAS / 远程访问** 场景的安全模型、现状盘点与分期落地计划。

> 行号证据基于 **v1.13.1**（2026-10-12）代码。

## 0. 背景与目标

### 0.1 场景

| 部署形态 | 暴露面 | 典型用户 |
| --- | --- | --- |
| Windows 单文件 exe | 仅本机 `127.0.0.1` | 个人桌面 |
| Docker / NAS（`0.0.0.0:8770`） | **局域网**，常配 nginx / Caddy / 群晖反代暴露到**公网** | 家庭 NAS，手机 / 电视 / 平板多端访问 |

内容为**极端敏感的个人收藏**：封面、观看历史、收藏与评分本身就是隐私，一旦泄漏无法补救。

### 0.2 需求来源

* **Issue #1 第 12 条**（NAS 用户 u2o，2026-10-14）三条明确建议：
  1. 增加**手动退出登录**；
  2. **令牌可设过期时间**；
  3. **容器重启后旧登录全部失效**，需重新验证；
  4. 现象补充："开着验证但不输密码也能访问，换隐私模式才弹窗"——即**登录态事实上永久有效**（前端 Cookie 写死 365 天）。
* **Issue #5**（skycc11，2026-10-15）：首页图片增加**模糊 / 无图**开关——防窥诉求。
* 作者规划（Issue #1 第 1 条）：本软件定位为"管理和观看自己收藏的本地影片"，因此安全设计要在**不牺牲开箱可用性**的前提下进行。

## 1. 现状盘点

### 1.1 认证与授权

| 项目 | 现状 | 证据 |
| --- | --- | --- |
| 认证方式 | 单一**静态全局令牌**，三通道：`X-Access-Token` 头 / `?token=` 查询 / `avm_token` Cookie | `app/main.py:48-67` |
| 令牌生成 | `secrets.token_urlsafe(24)`，可用 `AVM_ACCESS_TOKEN` 覆盖，明文存 `config.json` | `app/config.py:359-375` |
| 豁免路径 | `/`、`/index.html`、`/assets`、`/api/health`、**`/api/docs`**、`/api/openapi.json` | `app/main.py:30,75` |
| 本机豁免 | 仅按 `scope["client"][0]` 判断，命中即放行 | `app/main.py:33-35,80-81` |
| 多用户 / 角色 | **未实现** | `app/db.py` 无账户表 |
| 会话过期 / 轮换 | **未实现**（静态令牌，仅手动 `reset-token`） | `app/api.py:2057-2063` |

### 1.2 关键缺陷：反代下认证整体失效（P0）

全仓库**没有**任何 `X-Forwarded-For` / `proxy_headers` / `forwarded-allow-ips` / `TrustedHost` 处理（grep 命中 0）。

NAS 上反代（nginx / Caddy / 群晖）与容器**同机**，转发到后端时源 IP 恒为 `127.0.0.1` → `_is_local()` 判定为真 → **所有来自公网 / 局域网的请求都被当作"本机"直接放行**，整套访问控制形同虚设。

### 1.3 暴露面与响应头

| 项目 | 现状 | 证据 |
| --- | --- | --- |
| HTTPS / TLS | 不支持（uvicorn 无 `ssl_certfile`），无 HSTS、无强制跳转 | `app/cli.py:192` |
| CORS | `allow_origins=["*"]` + 全部方法 / 头 | `app/main.py:20-25` |
| 安全响应头 | 无（CSP / X-Frame-Options / nosniff / Referrer-Policy 均缺失） | grep 命中 0 |
| API 文档 | `/api/docs`、`/api/openapi.json` **免令牌公开**，可枚举全部接口与参数模型 | `app/main.py:18,30` |
| 异常回显 | 全局 handler 把异常文本直接返回客户端 | `app/main.py:207-209` |
| 健康检查 | 免令牌，且返回库规模等信息 | `app/api.py:2324-2328` |
| 出站 TLS | 封面下载**关闭证书校验**（`check_hostname=False`、`CERT_NONE`） | `app/images.py:201-203` |

### 1.4 敏感操作与凭据

**除统一令牌外无任何二次校验**：删除文件 / 影片、重置令牌、修改配置、导出全库 CSV、批量刮削、**调起服务端本机程序**（`POST /open-file`，`app/api.py:1323-1335`）都只依赖令牌。

令牌明文出现在多处：启动日志（`app/main.py:150-154`、`app/cli.py:183-188`）、`GET /api/server/info` 返回值与含 `?token=` 的 `access_urls`（`app/api.py:1880-1893`）、二维码（`app/api.py:2043-2046`）。

### 1.5 隐私与出站

服务端会主动联网，可能暴露 NAS 出口 IP 或库内数据：

| 出口 | 外发内容 | 证据 |
| --- | --- | --- |
| 检查更新 | GitHub Releases + 3 个第三方加速镜像 | `app/api.py:1929-2026,1966` |
| AI 增强 | 番号 / 标题 / 厂商 / 系列 / 女优 / 类型 / 简介 → `ai.base_url`（默认 OpenAI） | `app/ai.py:57-83` |
| 封面 / 头像 / 背景 | 向数据源图床下载落盘 | `app/images.py:135-161` |
| 维基女优资料 | `{lang}.wikipedia.org/api.php` | `app/plugins/wiki_actress.py:37,107-112` |
| gfriends 头像 | jsDelivr / raw.githubusercontent / ghproxy | `app/plugins/gfriends.py:21-29` |
| av-wiki 抓取 | 拉起 headless Chrome（`--no-sandbox`、profile 落 `data/chrome_profile`） | `app/cdp_fetch.py:239-250` |

### 1.6 数据落地与权限

`data/config.json` **明文**保存：`server.access_token`、`scraper.proxy`、javbus / javdb / avwiki 的整段浏览器 **Cookie**、`ai.api_key`。`data/chrome_profile/` 复用含站点 Cookie 的浏览器 profile。全仓无加密（grep `encrypt|Fernet` 命中 0）。

容器默认 `UMASK=022`（`docker/entrypoint.sh:11,14`、`Dockerfile:38-40`）→ 这些文件**组内 / 其他用户可读**。

### 1.7 前端

令牌存 `localStorage`（`avm_access_token`）+ 非 HttpOnly / 非 Secure Cookie（`avm_token`，**有效期 365 天**）—— `web_src/src/api.js:4,8-27`。这是"登录态永久有效"的直接原因。

`?token=` 会进入浏览器历史、反代 access log 与 `Referer`。

正面结论：前端**无 `v-html`**、**无第三方 CDN 脚本**（`web_src/index.html` 仅加载本地 `/src/main.js`），XSS 基础面较小。

## 2. 威胁模型

| # | 威胁 | 现实场景 | 影响 |
| --- | --- | --- | --- |
| T1 | **认证绕过** | 反代部署下源 IP 被当本机；或 `?token=` 从历史 / 日志泄漏 | 库与播放全量暴露 |
| T2 | **会话永不过期** | 手机借人、旧设备、公用平板仍持有效登录 | 隐私长期泄漏 |
| T3 | **凭据窃取** | 同机其他容器 / 进程、备份文件、日志读到 Cookie、AI key、令牌 | 数据源账号与 AI 额度被盗 |
| T4 | **窥屏** | 投屏、客厅电视、公共场合打开页面 | 内容尴尬 |
| T5 | **爆破与扫描** | 公网扫描器撞到 8770，尝试令牌 | 弱令牌被破（当前无任何限速与告警） |
| T6 | **信息泄漏** | `/api/docs` 暴露全部接口；异常回显内部路径 / 堆栈 | 攻击面扩大 |

**不在范围内**：国家级对手、物理接触主机、恶意浏览器扩展、宿主机 root 权限。

## 3. 设计原则

1. **开箱可用优先**：安全默认值不能把普通用户挡在门外（桌面 exe 保持本机免令牌）。
2. **显式优于隐式**：反代、代理、外联都必须显式声明，不猜测网络拓扑。
3. **默认收紧、可放宽**：危险开关（关闭验证、公开 docs、明文凭据）一律默认关闭并给出风险提示。
4. **失败安全**：认证组件异常时拒绝访问，而不是放行。
5. **可观测**：登录与敏感操作有记录，用户可自查"谁在什么时候登录过"。

## 4. 设计方案

### L1 会话与传输（P0）

**L1.1 令牌换会话**

把"静态令牌"升级为"服务端会话"（对标 Jellyfin 设备会话、Immich JWT、Audiobookshelf）：

| 环节 | 设计 |
| --- | --- |
| 登录 | `POST /api/auth/login` 提交令牌 → 校验后签发 `session_id`（`token_urlsafe(32)`），写 **HttpOnly / SameSite=Lax（HTTPS 时 Secure）** Cookie `avm_session`，**不再写入 localStorage 与可读 Cookie** |
| 存储 | **仅内存**（`sid → {created, last_seen, ip, ua}`），进程 / 容器重启即全部失效 → 直接满足 u2o 第 3 条 |
| 过期 | 空闲超时 `session_idle_days`（默认 7 天，每次访问续期）+ 绝对超时 `session_abs_days`（默认 30 天）→ u2o 第 2 条 |
| 登出 | `POST /api/auth/logout` 吊销当前会话；`POST /api/auth/logout-all` 吊销全部；前端顶栏与设置页提供入口 → u2o 第 1 条 |
| 一次性链接 | `?token=` 仅用于"换取会话"：校验通过后签发会话并 302 跳转到去掉参数的同路径，避免令牌进历史 / 日志 / Referer |
| CSRF | `SameSite=Lax` + 对 `POST/PUT/DELETE` 校验 `Origin`（缺失时回退 `Referer`）与 Host 同源；不一致直接 403 |
| 兼容 | `X-Access-Token` 头继续有效（脚本、第三方、旧客户端），但**不再等同登录**：它不进会话表，也不会被 `/server/info` 回显给远程用户 |

**L1.2 反代真实 IP（T1 根因修复）**

* 新增 `server.trusted_proxies`（默认 `["127.0.0.1", "::1"]`，即"只信任同机反代"），`app/auth.py:client_ip(scope, trusted)` 从右往左解析 `X-Forwarded-For`，取**第一个非信任跳**作为真实客户端 IP；无 XFF 时回退 `scope["client"][0]`。
* 启动 uvicorn 时开启 `proxy_headers=True`、`forwarded_allow_ips` 由 `trusted_proxies` 生成（`app/cli.py`）。
* 所有依赖客户端 IP 的逻辑（本机豁免、登录限速、审计）统一走 `client_ip()`。

**L1.3 本机豁免收敛**

* 新增 `server.local_bypass`：**桌面 exe 默认 `true`，容器内默认 `false`**（依据 `AVM_CONTAINER=1` 判定）。
* 理由：容器经端口映射 / 同机反代时无法区分"真本机"，开着等于对局域网完全放行。Docker 用户通过会话登录，体验不受影响（登录一次，Cookie 持久）。

### L2 认证硬化（P1）

| 能力 | 设计 | 对标 |
| --- | --- | --- |
| 登录失败限速 | `login_max_fails`（默认 5）/ `login_block_minutes`（默认 15）；同 IP 失败计数 → 指数退避 → 临时封禁；失败也计入审计 | Jellyfin `MaxFailedLoginAttempts`、群晖"自动封锁" |
| 审计日志 | 内存环形缓冲（最近 200 条：时间 / IP / UA / 事件 / 结果），`GET /api/auth/audit` 可查；二期可选落库 | Immich、DSM 登录记录 |
| 会话与设备管理 | `GET /api/auth/sessions` 列出活跃会话（IP / UA / 最后活动），`DELETE /api/auth/sessions/{sid}` 单个踢出 | Jellyfin 设备页 |
| 令牌重置 | 现有 `POST /server/reset-token` 增强：重置后**吊销全部会话** | — |
| 事务 API Key（P2） | `api_keys` 表：名称 / 作用域（只读、限定接口）/ 创建时间 / 最近使用 / **只存哈希**；与登录会话分离，可单独吊销 | Jellyfin API Key、Immich API Key |
| 二次验证（P2） | 可选 TOTP（设置页扫码绑定 + 备用码） | DSM、Jellyfin 插件 |

### L3 暴露面收敛（P1）

* **API 文档**：`/api/docs`、`/api/openapi.json` 移出免令牌白名单；新增 `server.expose_docs`（默认 `false`，即"仅登录后 / 仅本机可见"）。
* **CORS**：默认**关闭**（同源部署本不需要）；如需跨源，`server.cors_origins` 提供显式白名单。
* **安全响应头**（新增中间件，全站生效）：
  * `Content-Security-Policy: default-src 'self'; img-src 'self' data:; media-src 'self' blob:; style-src 'self' 'unsafe-inline'`（前端为本地打包资源，无需外域）
  * `X-Frame-Options: SAMEORIGIN`、`X-Content-Type-Options: nosniff`
  * `Referrer-Policy: no-referrer`（避免 `?token=` 经 Referer 外泄）
  * `Permissions-Policy: geolocation=(), microphone=(), camera=()`
  * HTTPS 下追加 `Strict-Transport-Security: max-age=31536000`
* **异常不回显**：改为 `{"detail": "服务内部错误", "request_id": "..."}`，堆栈只进服务端日志。
* **令牌不再回显给远程**：`GET /api/server/info` 仅本机返回完整令牌，远程返回掩码（`abc***xyz`）并置 `token_masked: true`；设置页"复制令牌"在远程时禁用并提示"请在本机操作"。
* **敏感操作二次确认**：删除文件 / 批量删除 / 导出 CSV / 重置令牌 增加一次性 `confirm` 参数校验；`POST /open-file` 限本机。
* **恢复出站 TLS 校验**：`app/images.py` 移除 `CERT_NONE`，改为可配 `server.insecure_skip_verify`（默认 `false`）。
* **健康检查瘦身**：免令牌的 `/api/health` 只返回 `{"ok": true, "version": ...}`，库规模等移入需认证的 `/api/stats`。

### L4 隐私与防窥（P1，对应 Issue #5）

> **实现状态（2026-10-15）**
> 已实现 ✅：空闲自动锁定（含"正在播放时不算空闲"）、紧急遮挡键（`privacy.panic_key`，默认 `Ctrl+Shift+H`）、标题中性化、切走自动暂停、
> 遮挡解锁方式三档（`privacy.lock_unlock`：`click` 点击即解锁 / `pin` 简单密码 / `token` 访问令牌，**空闲锁定与紧急遮挡通用**）。
>
> **锁定状态由服务端持有**（`POST /api/privacy/lock`）——这一点很关键：遮挡不再只是前端遮罩，
> 锁定期间中间件对除 `/api/privacy/*`、`/api/auth/*`、静态资源与 `/api/health` 以外的**所有请求返回 423**，
> 因此**刷新页面（F5）、重开标签页、绕过前端直接调接口，都拿不到封面 / 影片 / 流媒体**；前端遮挡层只是渲染器。
> 简单密码只以 PBKDF2-HMAC-SHA256 哈希落盘（`privacy.pin_hash`），明文不入库也不下发；解锁带失败限速。
>
> **忘记解锁凭据怎么办（应急出口）**：锁定在服务端，**刷新页面不再能解除**。按顺序尝试：
> ① 用访问令牌解锁（「设置 → 访问」本机可看到完整令牌，或读 `data/access_token.txt`）；
> ② 连令牌也无法使用时：停止服务 → 编辑 `data/config.json` 的 `privacy` 段，把 `lock_unlock` 改为 `"click"`、
> `lock_on_start` 改为 `false`（也可把 `idle_lock_minutes` 设为 `0` 关闭空闲锁定）→ 保存后**重启服务**；
> ③ 设置页已做保护：选择「简单密码」但尚未设置时不允许保存，避免把自己锁在门外。
> 待实现 ⏳：封面模糊 / 无图（`ui.cover_mode`）、标题脱敏（`ui.title_mode`）、出站总开关与透明化、日志脱敏。

| 能力 | 设计 |
| --- | --- |
| 三级显示策略 | `ui.cover_mode = normal / blur / hidden`。`blur` 为 CSS 模糊（悬停或点击显形）；**`hidden` 时后端直接把 `cover` / `fanart` / 预览图 URL 置空**（比前端遮盖更彻底，且不占带宽） |
| 紧急遮挡（"老板键"） | 快捷键（默认 `Ctrl+Shift+H`，可改）→ 立即遮挡全部内容并暂停播放；**恢复方式与空闲锁定一致**（`privacy.lock_unlock`：点击 / 简单密码 / 访问令牌），避免"按一下就解开"。移动端可加"摇一摇" |
| 标题脱敏 | `ui.title_mode = full / code / initial`（只显示番号 / 首字母），适用于投屏与客厅场景 |
| 播放器 | 默认静音启动（可记忆）；隐私模式下不预加载进度条缩略图与背景大图 |
| 出站总开关 | `privacy.offline_mode`（一键禁止全部外联：更新检查、AI、图片下载、维基、gfriends）；各出口另有独立开关，设置页集中展示"这个软件会连哪些网站、发什么数据" |
| AI 外发明示 | 面板内写明将发送的字段清单，默认关闭，支持自定义本地端点（Ollama 等） |
| 日志脱敏 | 刮削记录不写完整文件路径、不写外站 Cookie；导出的日志自动打码 IP 与令牌 |

### L5 数据与凭据保护（P1/P2）

| 能力 | 设计 |
| --- | --- |
| 文件权限 | 容器 `UMASK` 默认由 `022` 调整为 **`077`**；启动时对 `data/` 递归收紧为 `0700/0600`；文档提示 NAS 卷权限 |
| 凭据加密 | `server.master_password`（用户设定）经 PBKDF2-HMAC-SHA256 派生密钥，用 **AES-GCM** 加密 `config.json` 中的 `access_token` / `ai.api_key` / 各站 Cookie / `scraper.proxy`，密文以 `enc:v1:` 前缀标识；**未设主密码时保持明文，但文件权限收紧为 `0600` 并提示风险** |
| 备份 | 数据库每日备份（已有）可选加密；提示备份文件勿与 `data/` 同盘裸放 |
| 数据销毁 | 提供"清空观看历史 / 统计 / 刮削日志"一键操作（本地隐私） |
| 令牌文件 | 完整令牌写入 `data/access_token.txt`（权限 `0600`），启动日志只打印**掩码**与文件路径；Docker 取令牌方式改为 `docker compose exec avm cat /data/access_token.txt`（需同步更新 README 与部署文档） |

## 5. 配置项设计（新增）

`server` 段：

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `trusted_proxies` | `["127.0.0.1","::1"]` | 信任的反代 IP 列表，用于解析真实客户端 IP |
| `local_bypass` | exe `true` / 容器 `false` | 本机是否免令牌 |
| `session_idle_days` | `7` | 会话空闲超时（天），0 = 不过期 |
| `session_abs_days` | `30` | 会话绝对超时（天） |
| `cookie_secure` | `auto` | `auto` = 按请求协议自动决定 Secure 标志 |
| `login_max_fails` | `5` | 连续失败次数上限 |
| `login_block_minutes` | `15` | 触发后的封禁时长 |

## 7. 兼容与迁移

* **保留旧通道**：`X-Access-Token`、`?token=`、`avm_token` Cookie 继续可用，避免破坏脚本与旧客户端；但前端不再使用 `avm_token`，升级时主动清除该 Cookie。
* **升级即收紧**：老用户升级后若曾把 `local_bypass` 打开（或容器默认关闭本机豁免），首次访问会要求登录——**这是预期行为**，文档与更新说明需明确提示。
* **桌面 exe 无感**：`local_bypass=true`，本机访问体验与现在一致。
* **反代用户需配置**：README / 部署文档需新增"反代部署必读"小节（`trusted_proxies`、真实 IP、`X-Forwarded-Proto`、建议由反代终止 TLS）。
* **回滚路径**：所有新开关均可回退（关闭会话、恢复 `local_bypass=true`），保证出问题时能快速恢复可用。

## 9. 分期落地计划

### 第一期（P0，建议 1-2 天）—— 闭环 Issue #1 第 12 条

1. 反代真实 IP 与 `trusted_proxies`（含 uvicorn `proxy_headers`）；
2. 本机豁免收敛（`local_bypass`，容器默认关闭）；
3. 会话化：登录 / 登出 / 空闲与绝对过期 / **重启失效**；
4. 一次性链接改造（`?token=` 换会话后 302 去掉参数）；
5. `/api/docs` 与 openapi 移出白名单；
6. 安全响应头 + CORS 默认关闭 + 异常不回显；
7. 登录失败限速；
8. 令牌文件化（`data/access_token.txt`）+ 日志掩码 + `/server/info` 远程掩码；
9. 前端：登录框改造、顶栏 / 设置页"退出登录"、会话过期设置项、401 统一处理。

**验收标准**

* 反代（同机 127.0.0.1 转发）场景下，未登录请求返回 `401`；伪造 `X-Forwarded-For` 无法绕过；
* 登出后原 Cookie 立即失效；容器重启后全部会话失效；
* 空闲超过 `session_idle_days` 后需重新登录；
* 连续 5 次错误令牌后同 IP 被封禁 15 分钟，且有审计记录；
* `/api/docs`、`/api/openapi.json` 匿名访问返回 401；
* 响应头包含 CSP / nosniff / Referrer-Policy；
* 桌面 exe 本机访问体验与升级前一致。

## 10. 决策记录

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | 容器内 `local_bypass` 是否默认关闭 | **采纳**：容器（`AVM_CONTAINER=1`）默认 `false`，桌面 exe 默认 `true`，可用 `server.local_bypass` 覆盖 |
| 2 | 是否引入多用户 / 访客模式 | **本期不做**；未来确有家庭共享需求时，再考虑"访客视图（内容过滤 + 只读）" |
| 3 | HTTPS 形态 | **不做内置证书**：只提供反向代理文档与自签证书说明；后端识别 `X-Forwarded-Proto`，HTTPS 下自动追加 HSTS 与 Cookie `Secure` |
| 4 | 会话是否落盘 | **做成可配置**：`server.session_persist`（默认 `false` = 仅内存、重启即失效，符合用户诉求）；开启后会话以 **SHA-256 指纹**落盘 `data/sessions.json`，容器重启仍保持登录 |
