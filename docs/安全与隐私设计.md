# 片匣 · 安全与隐私设计

面向 **NAS / 远程访问** 场景的安全模型与分期落地计划。

## 0. 背景与目标

### 0.1 场景

| 部署形态 | 暴露面 | 典型用户 |
| --- | --- | --- |
| Windows 单文件 exe | 仅本机 `127.0.0.1` | 个人桌面 |
| Docker / NAS（`0.0.0.0:8770`） | **局域网**，常配 nginx / Caddy / 群晖反代暴露到**公网** | 家庭 NAS，手机 / 电视 / 平板多端访问 |

内容为**极端敏感的个人收藏**：封面、观看历史、收藏与评分本身就是隐私，一旦泄漏无法补救。

### 0.2 需求来源

* **Issue #1 第 12 条**（NAS 用户 u2o，2026-10-14）三条明确建议：
  1. 增加**手动退出登录**；
  2. **令牌可设过期时间**；
  3. **容器重启后旧登录全部失效**，需重新验证；
  4. 现象补充："开着验证但不输密码也能访问，换隐私模式才弹窗"——即**登录态事实上永久有效**。
* **Issue #5**（skycc11，2026-10-15）：首页图片增加**模糊 / 无图**开关——防窥诉求。
* 作者规划（Issue #1 第 1 条）：本软件定位为"管理和观看自己收藏的本地影片"，因此安全设计要在**不牺牲开箱可用性**的前提下进行。

## 1. 威胁模型

| # | 威胁 | 现实场景 | 影响 |
| --- | --- | --- | --- |
| T1 | **认证绕过** | 反代部署下源 IP 被当本机；或 `?token=` 从历史 / 日志泄漏 | 库与播放全量暴露 |
| T2 | **会话永不过期** | 手机借人、旧设备、公用平板仍持有效登录 | 隐私长期泄漏 |
| T3 | **凭据窃取** | 同机其他容器 / 进程、备份文件、日志读到 Cookie、AI key、令牌 | 数据源账号与 AI 额度被盗 |
| T4 | **窥屏** | 投屏、客厅电视、公共场合打开页面 | 内容尴尬 |
| T5 | **爆破与扫描** | 公网扫描器撞到 8770，尝试令牌 | 弱令牌被破 |
| T6 | **信息泄漏** | `/api/docs` 暴露全部接口；异常回显内部路径 / 堆栈 | 攻击面扩大 |

**不在范围内**：国家级对手、物理接触主机、恶意浏览器扩展、宿主机 root 权限。

## 2. 设计原则

1. **单一凭据**：访问令牌是唯一凭据，不区分本机 / 局域网 / 远程；桌面版靠「启动时用一次性短链打开浏览器」保持无感，而不是靠抛开认证。
2. **显式优于隐式**：反代、代理、外联都必须显式声明，不猜测网络拓扑。
3. **默认收紧、可放宽**：危险开关（关闭验证、公开 docs、明文凭据）一律默认关闭并给出风险提示。
4. **失败安全**：认证组件异常时拒绝访问，而不是放行。
5. **可观测**：登录与敏感操作有记录，用户可自查"谁在什么时候登录过"。

## 3. 设计方案

### L1 会话与传输（P0）

**L1.1 令牌换会话**

服务端会话模型（对标 Jellyfin 设备会话、Immich JWT、Audiobookshelf），令牌仅用于换取会话：

| 环节 | 设计 |
| --- | --- |
| 登录 | `POST /api/auth/login` 提交令牌 → 校验后签发 `session_id`（`token_urlsafe(32)`），写 **HttpOnly / SameSite=Lax（HTTPS 时 Secure）** Cookie；令牌不落 localStorage 与可读 Cookie |
| Cookie 名 | `avm_session_<数据目录哈希>`（可用 `AVM_COOKIE_NAME` 覆盖）。Cookie 以**主机名**为作用域、**不区分端口**，同机跑开发实例（8770）与容器（8771）时若同名会互相覆盖会话，表现为「刷新 / 播放时随机又要输令牌」——加后缀即根治 |
| 失效清理 | 任何 401 响应都会顺手 `Max-Age=0` 清掉已作废的会话 Cookie，避免浏览器一直带着死 sid 重试 |
| 存储 | **仅内存**（`sid → {created, last_seen, ip, ua}`），进程 / 容器重启即全部失效 → 直接满足 u2o 第 3 条 |
| 过期 | 空闲超时 `session_idle_days`（默认 7 天，每次访问续期）+ 绝对超时 `session_abs_days`（默认 30 天）→ u2o 第 2 条 |
| 登出 | `POST /api/auth/logout` 吊销当前会话；`POST /api/auth/logout-all` 吊销全部；前端顶栏与设置页提供入口 → u2o 第 1 条 |
| 一次性链接 | `?token=` 仅用于"换取会话"：校验通过后签发会话并 302 跳转到去掉参数的同路径，避免令牌进历史 / 日志 / Referer |
| CSRF | `SameSite=Lax` + 对 `POST/PUT/DELETE` 校验 `Origin`（缺失时回退 `Referer`）与 Host 同源；不一致直接 403 |
| 兼容 | `X-Access-Token` 头继续有效（脚本、第三方、旧客户端），但它**与登录态区分**：不进会话表，也不会被 `/server/info` 回显给远程用户 |

**L1.2 反代真实 IP（对应 T1）**

* `server.trusted_proxies`（默认 `["127.0.0.1", "::1"]`，即"只信任同机反代"），`app/auth.py:client_ip(scope, trusted)` 从右往左解析 `X-Forwarded-For`，取**第一个非信任跳**作为真实客户端 IP；无 XFF 时回退 `scope["client"][0]`。
* 启动 uvicorn 时开启 `proxy_headers=True`、`forwarded_allow_ips` 由 `trusted_proxies` 生成（`app/cli.py`）。
* 所有依赖客户端 IP 的逻辑（登录限速、审计来源）统一走 `client_ip()`。

**L1.3 取消本机豁免（单一令牌模型）**

* 旧的 `server.local_bypass`（本机免令牌）已**删除**：本机、手机、NAS 一视同仁，只有访问令牌这一个凭据。
* 理由：端口映射与同机反代本就无法可靠区分"真本机"，两个布尔（`local_bypass` × `require_token_remote`）还能组合出"完全开放"的危险状态。
* 桌面体验由启动逻辑补偿：`app/cli.py` 启动后用**一次性短链**（`?c=`，5 分钟、用一次失效）打开浏览器，令牌不进 URL / 历史 / 日志，用户无感。

### L2 认证硬化（P1）

| 能力 | 设计 | 对标 |
| --- | --- | --- |
| 登录失败限速 | `login_max_fails`（默认 5）/ `login_block_minutes`（默认 15）；同 IP 失败计数 → 指数退避 → 临时封禁；失败也计入审计 | Jellyfin `MaxFailedLoginAttempts`、群晖"自动封锁" |
| 审计日志 | 内存环形缓冲（最近 200 条：时间 / IP / UA / 事件 / 结果），`GET /api/auth/audit` 可查；二期可选落库 | Immich、DSM 登录记录 |
| 会话与设备管理 | `GET /api/auth/sessions` 列出活跃会话（IP / UA / 最后活动），`DELETE /api/auth/sessions/{sid}` 单个踢出 | Jellyfin 设备页 |
| 令牌重置 | `POST /server/reset-token` 重置令牌并**吊销全部会话** | — |
| 事务 API Key（P2） | `data/api_keys.json`（**只存 SHA-256 哈希**，权限 `0600`）：名称 / 作用域（`full` / `read`）/ 创建时间 / 最近使用；与登录会话分离，可单独吊销 | Jellyfin API Key、Immich API Key |
| 二次验证（P2） | 可选 TOTP（设置页扫码绑定 + 备用码） | DSM、Jellyfin 插件 |

### L3 暴露面收敛（P1）

* **API 文档**：`/api/docs`（自托管页面，**不引用任何 CDN**，离线 / 纯 http / 国内网络均可打开）与 `/api/openapi.json` 默认需登录；`server.expose_docs`（默认 `false`）控制是否允许匿名访问。
* **CORS**：默认**关闭**（同源部署本不需要）；如需跨源，`server.cors_origins` 提供显式白名单。
* **安全响应头**（新增中间件，全站生效）：
  * `Content-Security-Policy: default-src 'self'; img-src 'self' data:; media-src 'self' blob:; style-src 'self' 'unsafe-inline'`（前端为本地打包资源，无需外域）
  * `X-Frame-Options: SAMEORIGIN`、`X-Content-Type-Options: nosniff`
  * `Referrer-Policy: no-referrer`（避免 `?token=` 经 Referer 外泄）
  * `Permissions-Policy: geolocation=(), microphone=(), camera=()`
  * HTTPS 下追加 `Strict-Transport-Security: max-age=31536000`
* **异常不回显**：只回 `{"detail": "服务内部错误", "request_id": "..."}`，堆栈只进服务端日志。
* **令牌仅本机回显**：`GET /api/server/info` 仅本机返回完整令牌，远程返回掩码（`abc***xyz`）并置 `token_masked: true`；设置页"复制令牌"在远程时禁用并提示"请在本机操作"。
* **敏感操作二次确认**：删除文件 / 批量删除 / 导出 CSV / 重置令牌 需带一次性 `confirm` 参数校验；`POST /open-file` 限本机。
* **出站 TLS 校验**：图片下载 / 刮削 / 维基插件默认校验服务器证书；可用 `server.insecure_skip_verify`（默认 `false`）关闭。
* **健康检查最小化**：免令牌的 `/api/health` 只返回 `{"ok": true, "version": ...}`，库规模等移入需认证的 `/api/stats`。

### L4 隐私与防窥（P1，对应 Issue #5）

> **实现要点**
> 空闲自动锁定（含"正在播放时不算空闲"）、紧急遮挡键（`privacy.panic_key`，默认 `Ctrl+Shift+H`）、
> 标题中性化（可加自定义后缀 `privacy.site_subtitle` 作混淆，标题形如「片匣 - 我的资料库」）、切走自动暂停、
> **解锁只有两种凭据，都可主动输入**：`privacy.lock_unlock = pin`（快速解锁码，4~6 位，高频场景）
> 或 `token`（访问令牌）。**访问令牌始终可兜底** —— 忘了解锁码直接输令牌即可，反之亦然。
> 点击 / 任意键解锁（旧 `click` 模式）已移除：它防不住任何人，只会让人误以为安全。
>
> **锁定状态由服务端持有**（`POST /api/privacy/lock`）——这一点很关键：遮挡不只是前端遮罩，
> 锁定期间中间件对除 `/api/privacy/*`、静态资源与 `/api/health` 以外的**所有请求返回 423**，
> 因此**刷新页面（F5）、重开标签页、绕过前端直接调接口，都拿不到封面 / 影片 / 流媒体**；前端遮挡层只是渲染器。
>
> **未登录 / 已登出时首页返回登录页**（同样是 `app/lockpage.py` 渲染 + `/login.js`）：
> 与锁屏页共用一套 `.pv-*` 卡片，登出后不会先闪出应用外壳、也不会出现「角上浮一个小登录框」
> 与遮挡层两套观感。两步验证开启时先输令牌、再在同一张卡里切到验证码。
> `/api/privacy/unlock` 因此对未登录请求开放（凭据与限速都由该接口自己校验），
> 否则登出后触发锁定会陷入「锁屏页要凭据、中间件要会话」的死循环。
>
> **锁定期间首页直接返回独立锁屏页**（`app/lockpage.py` 渲染 + `/lock.js`），而不是 SPA：
> 否则刷新时浏览器会先下载并渲染应用、再请求 `/api/privacy/state` 才知道被锁，中间会闪一下
> 封面 / 标题 —— 这几十毫秒正是旁人能看到的窗口。
> 锁屏页样式与 SPA 内的遮挡层（`PrivacyLock.vue` 的 `.pv-*`）一致，文案按 `Accept-Language`
> 与锁定原因（空闲 / 老板键）、是否设了解锁码自动切换；不含任何应用数据，解锁成功后整页跳回 `/`。
> 解锁码只以 PBKDF2-HMAC-SHA256 哈希落盘（`privacy.pin_hash`），明文不入库也不下发；解锁带失败限速。
>
> **忘记解锁凭据怎么办（应急出口）**：锁定在服务端，**刷新页面不再能解除**。按顺序尝试：
> ① 用访问令牌解锁（「设置 → 访问」点「显示」后再输一次令牌，或读 `data/access_token.txt`）；
> ② 连令牌也无法使用时：停止服务 → 编辑 `data/config.json` 的 `privacy` 段，把 `lock_on_start` 改为 `false`、
> `idle_lock_minutes` 设为 `0` → 保存后**重启服务**；
> ③ 设置解锁码前请先确认令牌可用，避免把自己锁在门外。

| 能力 | 设计 |
| --- | --- |
| 三级显示策略 | `ui.cover_mode = normal / blur / hidden`。`blur` 为 CSS 模糊（悬停或点击显形）；**`hidden` 时后端直接把 `cover` / `fanart` / 预览图 URL 置空**（比前端遮盖更彻底，且不占带宽） |
| 紧急遮挡（"老板键"） | 快捷键（默认 `Ctrl+Shift+H`，可改）→ 立即遮挡全部内容并暂停播放；**恢复需要输入解锁码或访问令牌**（`privacy.lock_unlock`：pin / token），避免"按一下就解开"。移动端可加"摇一摇" |
| 标题脱敏 | `ui.title_mode = full / code / initial`（只显示番号 / 首字母），适用于投屏与客厅场景 |
| 播放器 | 默认静音启动（可记忆）；隐私模式下不预加载进度条缩略图与背景大图 |
| 出站总开关 | `privacy.offline_mode`（一键禁止全部外联：更新检查、AI、图片下载、维基、gfriends）；各出口另有独立开关，设置页集中展示"这个软件会连哪些网站、发什么数据" |
| AI 外发明示 | 面板内写明将发送的字段清单，默认关闭，支持自定义本地端点（Ollama 等） |
| 日志脱敏 | 刮削记录不写完整文件路径、不写外站 Cookie；导出的日志自动打码 IP 与令牌 |

### L5 数据与凭据保护（P1/P2）

| 能力 | 设计 |
| --- | --- |
| 文件权限 | 容器 `UMASK` 采用 **`077`**；启动时对 `data/` 递归收紧为 `0700/0600`；文档提示 NAS 卷权限 |
| 凭据加密 | `server.master_password`（用户设定）经 PBKDF2-HMAC-SHA256 派生密钥，用 **AES-GCM** 加密 `config.json` 中的 `access_token` / `ai.api_key` / 各站 Cookie / `scraper.proxy`，密文以 `enc:v1:` 前缀标识；**未设主密码时保持明文，但文件权限收紧为 `0600` 并提示风险** |
| 备份 | 数据库每日备份（保留最近 7 份）可选加密；提示备份文件勿与 `data/` 同盘裸放 |
| 数据销毁 | 提供"清空观看历史 / 统计 / 刮削日志"一键操作（本地隐私） |
| 令牌文件 | 完整令牌写入 `data/access_token.txt`（权限 `0600`），启动日志只打印**掩码**与文件路径；容器内取令牌：`docker compose exec avm cat /data/access_token.txt` |

## 4. 配置项设计（新增）

`server` 段：

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `trusted_proxies` | `["127.0.0.1","::1"]` | 信任的反代 IP 列表，用于解析真实客户端 IP |
| `token_required` | `true` | **访问保护**：所有设备（含本机）是否必须令牌；关闭则完全开放（旧键 `require_token_remote` 自动迁移） |
| `session_idle_days` | `7` | 会话空闲超时（天），0 = 不过期 |
| `session_abs_days` | `30` | 会话绝对超时（天） |
| `session_persist` | `false` | 会话是否落盘（SHA-256 指纹存 `data/sessions.json`）；`false` = 仅内存，重启即失效 |
| `login_max_fails` | `5` | 连续失败次数上限 |
| `login_block_minutes` | `15` | 触发后的封禁时长 |
| `expose_docs` | `false` | 是否允许匿名访问 `/api/docs` |
| `cors_origins` | `[]` | 跨源白名单，空 = 关闭 CORS |
| `security_headers` | `true` | 是否下发 CSP / nosniff / Referrer-Policy 等安全响应头 |
| `insecure_skip_verify` | `false` | 出站 HTTPS 跳过证书校验（不推荐） |

`ui` / `privacy` 段：

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `ui.cover_mode` | `normal` | `normal` / `blur` / `hidden`（Issue #5） |
| `ui.title_mode` | `full` | `full` / `code` / `initial` |
| `privacy.offline_mode` | `false` | 一键禁止全部外联 |
| `privacy.allow_update_check` | `true` | 更新检查外联 |
| `privacy.allow_ai` | `false` | AI 外发（与 `ai.enabled` 联动） |
| `privacy.allow_image_download` | `true` | 封面 / 头像下载 |

## 5. 接口设计（新增）

| 方法 | 路径 | 说明 | 鉴权 |
| --- | --- | --- | --- |
| `POST` | `/api/auth/login` | 令牌换会话，Set-Cookie | 需令牌 |
| `POST` | `/api/auth/logout` | 吊销当前会话 | 会话 / 令牌 |
| `POST` | `/api/auth/logout-all` | 吊销本机全部会话 | 会话 / 令牌 |
| `GET` | `/api/auth/session` | 当前会话状态（是否登录、过期时间、是否本机） | 放宽（未登录返回 `authenticated: false`） |
| `GET` | `/api/auth/sessions` | 活跃会话列表 | 会话 |
| `DELETE` | `/api/auth/sessions/{sid}` | 踢出指定会话 | 会话 |
| `GET` | `/api/auth/audit` | 最近登录 / 失败记录 | 会话 |
| `GET` | `/api/privacy/state` | 锁定状态、解锁方式（pin / token）、是否已设解锁码 | 白名单（锁定时仍可访问） |
| `POST` | `/api/privacy/lock` | 进入锁定（空闲超时 / 老板键触发） | 会话 / 令牌 |
| `POST` | `/api/privacy/unlock` | 解锁（凭据为解锁码或访问令牌，任一即可） | 白名单（锁定时仍可访问） |
| `POST` | `/api/auth/set-pin` | 设置 / 清除快速解锁码（PBKDF2 哈希） | 会话 |
| `GET` | `/api/auth/totp` | 两步验证状态（是否启用、剩余备用码） | 会话 / 令牌（API Key 不可用） |
| `POST` | `/api/auth/totp/setup` | 生成密钥与 otpauth 链接（此时尚未启用） | 会话 / 令牌（API Key 不可用） |
| `GET` | `/api/auth/totp/qr` | 待确认密钥的二维码（PNG，密钥不进 URL / 日志） | 会话 / 令牌（API Key 不可用） |

## 6. 兼容与迁移

* **保留旧通道**：`X-Access-Token`、`?token=`、`avm_token` Cookie 继续可用，避免破坏脚本与旧客户端；前端使用会话 Cookie，升级时主动清除 `avm_token`。
* **升级即收紧**：`local_bypass` 已删除，老配置里的该键被忽略；升级后**首次访问一律要求令牌**（桌面 exe 会先用一次性短链打开浏览器，实际无感）。
* **反代用户需配置**：`trusted_proxies`、真实 IP、`X-Forwarded-Proto`，建议由反代终止 TLS（见部署文档）。
* **回滚路径**：恢复可用只需关闭访问保护（`token_required=false`）或更换令牌；旧版的 `local_bypass` 不再生效。

### 9.2 NAS 上线检查清单

1. **保持访问保护开启**（`server.token_required = true`，默认值）。关掉等于对局域网完全开放。
2. **`server.trusted_proxies`**：同机反代默认已含 `127.0.0.1, ::1`；反代若在**其它主机 / 容器**，必须把它的地址加进去，否则真实客户端 IP 解析不到，登录限速与审计来源都会失真。
3. **HTTPS**：让反代传 `X-Forwarded-Proto: https`，会话 Cookie 会自动加 `Secure`、响应自动加 HSTS，无需额外配置。
4. **令牌怎么取**：任何已登录会话的「设置 → 访问」点「显示」即可查看完整令牌，但**需要再输入一次当前令牌**（明文 30 秒后自动隐藏，防会话被劫持后抄走长期凭据）；容器内可 `cat /data/access_token.txt`。令牌疑似泄漏时用「立即登出并更换令牌」一次完成轮换 + 全设备登出。
   二维码里装的是**一次性短链**（`?c=<code>`，默认 5 分钟、用一次即失效），不含长期令牌，
   已登录会话都能生成 —— 容器 / NAS（来源 IP 恒为网关）同样可用。
   只有事务 API Key 这类低权限机器凭据只拿到掩码。
5. **会话策略**：保持 `session_persist = false`，容器 / NAS 重启后所有设备都需重新登录（对应 Issue #1 第 12 条第 3 点）。
6. **定期自查**：「设置 → 访问」查看活跃会话与登录失败记录，发现陌生 IP 立即「踢出」或「退出全部设备」。
7. **分享链接**：`http://<host>/?token=xxx` 可一次性打开（打开即换成会话，地址栏随即变干净），但**不要**把它长期写进书签或群聊。

| --- | --- | --- |
| 1 | 本机 / 远程是否区别对待 | **已改为单一令牌**：删除 `local_bypass`，任何来源都要令牌；桌面体验由「启动时一次性短链打开浏览器」补偿。理由：两个布尔能组合出"完全开放"，且容器里"真本机"本就不可判定 |
