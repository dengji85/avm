# AI 功能现状与设计讨论（草案）

> 状态：讨论稿，未进入实现。整理现有能力、已知问题、四个改造诉求与可集成方案，
> 供后续统一规划。最后更新：2026-10-24。

## 1. 现有能力

| 模块 | 位置 | 现状 |
|---|---|---|
| 剧情简介 | 详情页 AI 工作台 | 字幕 → 语音对白 → 元数据三级回退；先预览后采用；记录来源（`ai-subtitle` / `ai-dialog` / `ai-meta`） |
| 标签建议 | 详情页 | 一次 3–8 个，已有标签默认不勾选，逐条确认后写入 |
| 字幕翻译 | 详情页 | 日→中、可双语，生成 `AI 译文` 字幕轨，可删除（含文件） |
| 剧情问答 | 详情页 | 基于字幕/对白分句，回答带时间戳，点击跳转播放位置 |
| 相似推荐 | 详情页 | 女优/系列/厂商/标签/剧情相似，附理由 |
| 提示词 | 详情页「提示词」tab | 8 条 system 提示词可查看、编辑、恢复默认 |
| 调用详情 | 详情页「调用详情」 | 每次调用的 system/user/回复/耗时/缓存命中（内存 80 条） |
| 批量任务 | 设置页 | 剧情分析 / 字幕翻译，限并发、可取消 |
| 语音对白提取 | 详情页对白卡 | faster-whisper，10 分钟切片逐段识别；产物 `dialog.txt` + `segments.json` |
| 草稿字幕 | 详情页对白卡 | 有对白即可导出 SRT 并登记为字幕轨（旧数据用推算时间轴） |
| 硬字幕/外挂字幕 | 扫描与字幕区 | 外挂字幕自动登记；硬字幕仍靠 OCR 工具 |

## 2. 现存问题

### 2.1 交互层

1. **AI 工作台过载**：把剧情、标签、翻译、问答、相似、提示词、调用日志、语音提取、草稿字幕全部塞进一个抽屉，入口只有一个「AI 助手」，新用户不知道从哪开始。
2. **两套导航**：详情页有「任务 / 提示词」两个视图，设置页又有「AI 批量任务」和「提示词」入口，同一功能有两个家。
3. **播放中不可用**：播放器全屏后无法打开 AI（问答、翻译、场景跳转），必须退出到详情页。
4. **模型配置是单例**：`ai.base_url / api_key / model` 只有一套，换模型必须改配置，无法并存比较。
5. **结果无法并排比较**：同一提示词换模型只能手动改配置、重跑、记忆对比。

### 2.2 架构层

1. **AI 与业务耦合**：剧情、标签、翻译、问答的编排逻辑散在 `api.py`，新增能力（场景索引、结构化档案）会继续膨胀。
2. **提示词与调用参数绑定在全局配置**：没有「每个任务用哪套提示词/哪个模型」的任务级配置。
3. **调用记录只在内存**：80 条环形缓冲，重启即丢，无法做长期质量分析。
4. **无断点续跑**：批量任务中途失败需要整体重跑；大批量（500+）不可行。
5. **无审核队列**：剧情靠预览、标签靠勾选，但字幕翻译直接落盘，批量场景缺少统一的「AI 产出待审」层。

### 2.3 数据层

1. **AI 产出不可检索**：简介是散文，标签是自由词，没有结构化字段（场景、人物、题材），搜索只能命中标题/番号。
2. **标签失控风险**：AI 会造近义词（「人妻」「已婚」「主妇」），半年后筛选不可用。
3. **女优/系列名称不规范**：AI 可能写出变体（上田纱奈 / 上田紗奈），与既有女优表对不上。
4. **缺少场景级时间轴**：只有对白时间点，没有「第 12 分钟在办公室、第 46 分钟在车内」这类索引。

### 2.4 成本与隐私

1. **云端请求无提示**：配置云端模型后，字幕/对白文本会外发，界面上没有明确告知。
2. **成本不可见**：只记录调用次数与字符数，没有按模型的费用估算。
3. **无本地模型优先策略**：Ollama 可以直连，但没有「敏感内容只走本地」的规则。

### 2.5 工程债（已知）

| 项 | 说明 |
|---|---|
| 提示词无 A/B | 改了提示词无法对比改前/改后效果 |
| 前端单包 1.3MB | 无按需加载，AI 面板与播放器同包 |
| 无自动化测试 | AI 相关只有手工接口验证 |
| ASR 分段边界 | 10 分钟切片处可能截断一句话 |
| 旧对白无时间轴 | 旧数据导出字幕用推算（每条 ≤8 秒） |

## 3. 四个改造诉求与设计方向

### 3.1 多模型与结果对比

**目标**：同一任务（剧情/标签/问答）可选多个模型并排跑，直接比较后采用一个。

设计要点：

- **模型池**：`[{name, base_url, api_key, model, temperature, 备注, 是否本地}]`，不再只有一套配置。
- **任务级选择**：每个任务可选「默认模型」或「对比模式」；对比模式下并行请求 2–4 个模型。
- **并排 diff**：两列/多列展示，差异高亮；标注长度、耗时、token 估算、缓存命中。
- **采用与统计**：采用某一列后记录 `winner`，累计每个模型的胜出率与失败率，用于后续默认值。
- **成本控制**：对比模式只在详情页手动触发，批量任务仍用单模型。

可选现成方案（评估后决定自研还是集成）：

- [LiteLLM](https://github.com/BerriAI/litellm)：统一 100+ 提供方为 OpenAI 兼容接口，带路由、重试、成本统计。若自建「模型池 + 计费」，它可作中间层，后端只保留一套调用代码。
- [Open WebUI](https://github.com/open-webui/open-webui)：原生支持多模型并排对比，可独立部署作为「外部 AI 面板」，片匣只负责喂上下文。
- 自研（推荐先走这条）：只在现有 `ai_core` 上加「模型列表 + 并行调用 + 结果表」，改动可控，不需要额外服务。

### 3.2 UI 拆分

**目标**：详情页轻、中心页全、播放器可呼出。

建议的三层结构：

| 层 | 内容 | 入口 |
|---|---|---|
| 详情页（轻） | 4 个高频动作：生成简介 / 加标签 / 问一句 / 翻译；结果卡直接展示 | 详情页「AI」按钮 |
| AI 中心（全） | 模型池、提示词、任务队列、对比实验、调用日志、用量/成本、语音组件、草稿字幕 | 侧栏或设置内独立页 `/ai` |
| 播放器（浮层） | 问答、翻译开关、场景跳转；不遮挡画面 | 播放器右上角「AI」 |

拆分原则：**凡是一次性配置（模型、提示词、日志、组件状态）都不进详情页**；详情页只保留「对这部片做什么」。

### 3.3 统一管理中心 + 播放时可用

- 新增 `/ai` 页面：左侧导航（模型 / 提示词 / 任务 / 对比 / 日志 / 用量 / 语音），右侧内容区。
- 详情页与播放器共用一套 composable 与状态，模型/提示词修改后即时生效。
- 播放器内改为**右侧抽屉**（占 380px，可收起），支持：
  - 对当前片提问（复用问答接口）
  - 一键开关 AI 译文轨
  - 场景/对白时间点列表，点击跳转
- 抽屉状态跨页面保留（同片切换不丢上下文）。

### 3.4 可集成的开源项目

按「价值 / 成本 / 风险」筛选，2026-10 时点可用：

| 类别 | 项目 | 用途 | 成本 | 建议 |
|---|---|---|---|---|
| 多模型网关 | **LiteLLM** | 统一多厂商 API、成本统计、重试 | 中 | 若模型数 >3 再引入 |
| 多模型对比 UI | **Open WebUI** / **LibreChat** | 独立 AI 面板，多模型并排、RAG | 低（独立部署） | 可先作为「外挂面板」试水 |
| 本地推理 | **Ollama** / **llama.cpp** / **LM Studio** | 本地模型，隐私场景 | 低 | 已支持 OpenAI 兼容，直接可用 |
| 视频理解 | **Qwen2.5-VL-3B/7B**（Apache 2.0） | 抽帧理解画面、生成场景描述、秒级事件定位 | 高（需 GPU） | 场景索引阶段再上 |
| 视频理解 | **InternVL2.5-8B** / **MiniCPM-V 2.6** | 同类，中文/端侧友好 | 高 | 备选 |
| 场景分割 | **PySceneDetect** | 自动切分场景，生成章节时间轴 | **低** | **推荐优先**：无模型依赖，纯 CPU |
| OCR | **RapidOCR**（ONNX）/ **PaddleOCR** | 硬字幕提取 | 中 | 已有讨论，按需 |
| 语音 | **faster-whisper** / **WhisperX** | 对白转写 / 词级时间戳 | 低 | 已用，WhisperX 可提升时间轴 |
| 语音 | **SenseVoice** | 中文/粤语识别，速度快 | 低 | 中文片优先时替换 |
| 说话人分离 | **pyannote-audio** | 区分说话人 | 中（需 HF token） | 对白多人场景可选 |
| 图像增强 | **Real-ESRGAN** | 封面/截图超分 | 低（CPU 可用） | 提升资料库观感 |
| 抠图 | **rembg** | 女优头像去背景 | 低 | 可选 |
| 人脸修复 | **GFPGAN / CodeFormer** | 老片封面修复 | 中 | 可选 |
| 人物识别 | **InsightFace** | 女优识别/聚类 | 中（误识别、隐私） | 谨慎，需人工确认 |
| 图搜 | **CLIP / SigLIP** + **Qdrant/Chroma** | 以图搜片、相似构图 | 中 | 场景索引之后 |
| 自动化 | **n8n** | 夜间批量、外部通知 | 低 | 可选，非核心 |

**我的判断**：

- 真正能立刻提升的是 **PySceneDetect**（章节/场景时间轴，纯 CPU、无模型）与 **LiteLLM 式模型池**（自研即可）。
- **Qwen2.5-VL** 能力最强，但需要 GPU 与显存，属于「看片理解」的下一阶段。
- **Open WebUI** 适合当试验田：先把多模型对比在外部跑通，再决定是否内置。

## 4. 需要拍板的决策

| # | 问题 | 选项 |
|---|---|---|
| 1 | 多模型对比放在哪 | A 自研并排（推荐）/ B 集成 Open WebUI / C 两者都要 |

| 3 | 详情页保留哪些动作 | A 四项（剧情/标签/问答/翻译）/ B 只留剧情与问答 |
| 4 | 播放器 AI 入口形态 | A 右侧抽屉 / B 底部弹层 / C 新窗口 |

| 6 | 结构化档案是否做 | A 做（受控词表）/ B 先只做标签规范化 / C 暂缓 |

## 5. 建议演进路线

| 阶段 | 目标 | 关键动作 | 预估 |
|---|---|---|---|
| **S1 拆分与多模型** | 详情页变轻、能对比 | 新增 `/ai` 中心页；模型池；对比视图；提示词/日志/语音迁移过去 | 3–5 天 |
| **S2 可检索** | AI 产出能搜 | 受控标签表 + 结构化档案字段 + FTS 索引 + 审核队列 | 4–6 天 |
| **S3 场景感知** | 按场景定位 | PySceneDetect 切场景 → 对白对齐 → 章节列表；VLM 描述作为可选增强 | 3–4 天（不含 VLM） |
| **S4 播放器与推荐** | 边看边用 | 播放器右侧抽屉；AI 译文一键开关；基于观看行为的推荐片单 | 3–4 天 |

## 6. 附：当前技术参数（便于估算）

- 单次剧情调用：约 3–5 秒，成本约 1–3 千 token（取决于字幕长度）。
- 标签：约 2 秒。
- 字幕翻译：按 100 条分段，每段 2–4 秒。
- ASR（small，CPU）：约 4× 实时；2 小时片约 30–40 分钟，临时 wav 约 230 MB（可配置目录）。
- 模型体积：small 464 MB / medium 1.5 GB，均不随程序打包。
