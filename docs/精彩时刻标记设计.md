# 精彩时刻标记 · 实现方案与 Stash 对照

> **状态**：P0 / P1 / P2 已实施（2026-11-12） ｜ 参考实现：Stash `SceneMarker`
>
> 本文记录「精彩时刻」为什么这样设计、数据与接口如何约定、哪些能力刻意不做。落地进度以 `CHANGELOG.md` 为准；文中代码位置基于 2026-11-12 的快照，行号可能随改动漂移。

---

## 1. 目标与边界

### 1.1 要解决的体验问题

片头片尾跳过只能表达「整片一个点」，用户真正的需求是「这部片第 12:30–13:05 好看，第 48 分还有一段」。第一版只做到「点一下按钮、固定 30 秒、没有缩略图」，因此：

| 问题 | 用户感受 |
|---|---|
| 打点必须开菜单点按钮 | 看到精彩处手忙脚乱，错过就没了 |
| 卡片只有时间文本 | 分不清是哪一段，要逐个点开确认 |
| 不能改名字 / 起止 / 标签 | 事后无法整理，等于一次性便签 |
| 没有主标记 | 50 段里挑不出「最想推荐的那段」 |
| 详情页没有标记区 | 不播放就看不到这部片标了什么 |

### 1.2 明确不做

| 不做 | 理由 |
|---|---|
| 每个标记生成雪碧图 / 多码率版本 | 雪碧图只服务进度条 hover，本项目的悬停场景在标记卡片上，直接播 4 秒 mp4 更直观；多码率会让一次打点变成多次转码，收益不足 |
| 主标记必填「主标签」 | Stash 的 primary tag 是分类入口（它的 Markers 页按主标签分组）。本项目的标签筛选不依赖主标签，只保留「唯一主标记」这一层语义 |
| 标记墙的独立 CRUD / 编辑页 | 标记编辑需要播放位置与画面上下文；墙上只做浏览、筛选与跳转，编辑仍回播放器 ⚑ 面板 |
| 新增第二个悬浮入口 | 播放器里 ⚑ 面板已经是「片头 / 片尾 / 标记」的统一入口，再加一个浮层只会让用户不知道该点哪个 |
| 每标记独立存储截图 / 视频文件树 | 缩略图与预览短片按 `<movie_id>/<marker_id>.jpg|mp4` 落到 `data/covers/marker/`，随影片级联清理，不建独立目录体系 |
| 新增除「预览开关 / 占用上限」外的配置项 | 时长、宽度、编码都是常量；只把「要不要生成」和「最多占多少磁盘」交给用户 |

## 2. Stash 参考

### 2.1 数据模型

`SceneMarker`（GraphQL 类型，字段按官方 schema 归纳）：

| 字段 | 说明 | 本项目 |
|---|---|---|
| `id` | 主键 | 采纳（`movie_markers.id`） |
| `scene` | 所属场景（必填，级联删除） | 采纳，改为 `movie_id`（`ON DELETE CASCADE`） |
| `title` | 标记标题（必填短文本） | 改写为 `label`（可空，≤40 字）——打点时不该被迫输入 |
| `seconds` | 起点（秒，浮点） | 采纳为 `start_sec` |
| `end_seconds` | 终点（可选，Stash 后期加入） | **改写为一等公民** `end_sec`（必填，> start）——本项目的进度条按区间绘制 |
| `primary_tag` | 主标签（必填 `Tag`） | **不采纳**，改为 `is_primary` 布尔（每片唯一） |
| `tags` | 附加标签数组 | 采纳，落到关联表 `movie_marker_tag`（复用 `tags` 词表） |
| `created_at` / `updated_at` | 时间戳 | 采纳 `created_at`；未加 `updated_at`（无排序 / 同步需求） |
| `screenshot` | 服务端自动生成的静帧 URL | 采纳为 `thumb`（相对名，经 `/api/covers/marker/...` 下发） |
| `preview` | 几秒预览短片 | **P2 采纳**：4 秒静音 H.264 循环 mp4（宽 480），与缩略图同目录、`<id>.mp4` 区分 |
| `stream` | 预览短片的流式地址 | 不采纳：本地文件直接走 `FileResponse`，浏览器原生 `<video>` 循环播放 |

标签池：Stash 的标记标签与场景标签共用一个 `Tag` 表，标记因此能出现在标签筛选里。

**本项目采纳这一点，但隔离了影片 facet**：标记标签写进现有 `tags` 词表（复用 `store.ensure_tag`，不重复造词），但只通过 `movie_marker_tag` 关联，**不写入 `movie_tags`**。这样「影片库按类型筛选」「类型统计」不会被标记标签污染，而 `tags` 表仍是单一真源，重命名 / 清理逻辑不用写第二套。

### 2.2 交互

| Stash 的交互 | 本项目 |
|---|---|
| 场景页 Markers 标签页列出全部标记（缩略图 + 标题 + 时间） | 采纳，落在播放器 ⚑ 面板与详情页标记区 |
| 场景页快捷键 `k` 新建标记（打开表单填标题与标签） | 采纳思路，改为 `M` **一键打点**（起点=当前画面，终点=+30 秒，零表单） |
| 核心不提供区间快捷键，`M` / `Shift+M` 由 Quick Tools 插件提供 | 不照搬；本项目区间是刚需，`M` 直接进核心 |
| Markers 页面按主标签分组浏览 | 不采纳（无标记墙）；P2 再评估按标签筛选 |
| 截图由服务端任务异步生成，不阻塞保存 | 采纳，`submit_task` + 失败静默 |
| 标记可编辑标题 / 时间 / 标签，可删除 | 采纳，面板内联编辑 |
| 时间轴（进度条）上绘制标记 | 采纳，并加「唯一主标记」加亮 |
| 与章节（Chapters）的区别：章节是文件级、连续、全覆盖；标记是片段级的「书签」 | 采纳该定位：本项目不做章节，标记即片段书签 |

### 2.3 「Stash 为什么好用」的结论

- **数据模型带来的**：标签与影片共用词表 → 标记天然进入既有筛选体系；截图由服务端生成 → 列表可扫视；`primary_tag` 保证「每个标记有归属」。
- **交互细节带来的**：一键打点（按当前播放位置，不用输时间）、列表就地跳转、就地编辑、时间轴可视化。
- 本项目拿走了全部「交互细节」与「截图异步生成」；在模型上只做两处取舍——区间必填（因为进度条按区间画）、主标签换成唯一主标记（因为没有标记墙）。

## 3. 数据模型

### 3.1 `movie_markers`

```sql
CREATE TABLE IF NOT EXISTS movie_markers (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    movie_id   INTEGER NOT NULL REFERENCES movies(id) ON DELETE CASCADE,
    start_sec  REAL    NOT NULL DEFAULT 0,
    end_sec    REAL    NOT NULL DEFAULT 0,
    label      TEXT    DEFAULT '',
    kind       TEXT    DEFAULT 'marker',    -- marker / favorite
    color      TEXT    DEFAULT '',          -- 预留：#rgb / #rrggbb
    sort       INTEGER DEFAULT 0,
    is_primary INTEGER DEFAULT 0,           -- 唯一主标记
    thumb      TEXT    DEFAULT '',          -- 相对名 marker/<movie_id>/<id>.jpg
    created_at TEXT    DEFAULT (datetime('now','localtime'))
);
CREATE INDEX IF NOT EXISTS idx_markers_movie ON movie_markers(movie_id, start_sec);
```

### 3.2 幂等迁移（`app/db.py`）

老库已存在 `movie_markers`（P0 之前的 4 列版本），因此**新列与新索引不能写进 SCHEMA 的 `executescript`**：索引会先于 `ALTER TABLE` 执行而报 `no such column: is_primary`，整个启动失败。

| 步骤 | 语句 | 说明 |
|---|---|---|
| 1. 补列 | `PRAGMA table_info(movie_markers)` → 缺则 `ALTER TABLE ... ADD COLUMN is_primary INTEGER DEFAULT 0` / `thumb TEXT DEFAULT ''` | 只加列，不改既有列定义 |
| 2. 关联表 | `CREATE TABLE IF NOT EXISTS movie_marker_tag(marker_id, tag_id, PRIMARY KEY(marker_id, tag_id))`，两列均 `ON DELETE CASCADE` | 放在 ALTER 之后 |
| 3. 索引 | `idx_marker_tag(tag_id)` | 按标签反查标记（P2 用） |
| 4. 部分唯一索引 | `CREATE UNIQUE INDEX IF NOT EXISTS idx_markers_primary ON movie_markers(movie_id) WHERE is_primary = 1` | 数据库侧兜底「每片至多一个主标记」 |

重复执行不报错（全部 `IF NOT EXISTS` + 列存在判断），符合 `AGENTS.md` 第 6 节「迁移要幂等」。

### 3.3 为什么是部分唯一索引

主标记的唯一性靠两层：

- **接口层**：`POST` / `PUT` 带 `is_primary` 时先 `UPDATE movie_markers SET is_primary = 0 WHERE movie_id = ?`，再写本行；
- **数据库层**：部分唯一索引 `WHERE is_primary = 1`，即使并发或代码回归出现两条主标记，也会被约束拦下（返回 500 而不是静默脏数据）。

不用「主标记 id 存到 movies 表」的方案：那需要两处同步、删除时要清字段、迁移时要回填，成本高于部分索引。

### 3.4 标签为什么不建独立词表

`movie_marker_tag` 只存 `(marker_id, tag_id)`，标签名仍在 `tags` 表：

- 与影片共用 `store.ensure_tag(conn, name)`，同名标签只存一行，重命名 / 清理不用两套逻辑；
- 标记标签**不写 `movie_tags`**，所以影片库的类型筛选、统计口径完全不受影响；
- 删除标记时先删关联行（`foreign_keys=ON` 下也可依赖级联），不删 `tags` 里的词，避免影响其他影片 / 标记。

## 4. 接口契约

全部挂在 `/api` 前缀下（`app/routers/markers.py`，在 `api.py` 中 `include_router`）；鉴权沿用全局访问令牌 / API Key。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/movies/{movie_id}/markers` | 列出该片全部标记（按起点排序），顺带补老标记缩略图 |
| POST | `/api/movies/{movie_id}/markers` | 新建标记；首条自动成为主标记 |
| PUT | `/api/movies/{movie_id}/markers/{marker_id}` | 部分更新（只传需要改的字段） |
| DELETE | `/api/movies/{movie_id}/markers/{marker_id}` | 删除；若删的是主标记，自动扶正最早一条 |
| GET | `/api/covers/marker/{movie_id}/{fname}` | 缩略图（`image/jpeg`，路径穿越校验） |
| GET | `/api/markers` | 标记墙：跨影片分页列出标记，可按标签 / 影片筛选 |

### 4.1 字段

| 字段 | 类型 | 读写 | 约束 |
|---|---|---|---|
| `id` | int | R | — |
| `movie_id` | int | R | 影片必须存在，否则 404 |
| `start` / `end` | float（秒） | R/W | 非负；`end > start`；单段 ≤ 30 分钟；`end` 不超过影片时长 +1s |
| `label` | str | R/W | ≤ 40 字，可空 |
| `kind` | str | R/W | `marker` / `favorite`，默认 `marker` |
| `color` | str | R/W | 空或 `#rgb` / `#rrggbb` |
| `primary` | bool | R/W（写用 `is_primary`） | 每片唯一；首条自动为真 |
| `thumb` | str | R | 相对名，空串表示未生成 / 无本地文件 |
| `tags` | str[] | R/W | 也接受 `,，、;；` 分隔的字符串；≤ 8 个，单个 ≤ 20 字，去重保序 |
| `created_at` | str | R | 本地时间文本 |

响应统一为 `{"ok": true, "item"|"items": ...}`；列表额外返回 `max`（当前为 50，前端据此禁用「新增」并提示）。

### 4.2 校验规则与文案口径

| 规则 | HTTP | `detail` |
|---|---|---|
| 影片不存在 | 404 | 影片不存在 |
| 标记不存在 / 不属于该片 | 404 | 标记不存在 |
| 起止不是数字 | 400 | 起止时间必须是秒数 |
| 起止为负 | 400 | 起止时间不能为负数 |
| `end <= start` | 400 | 结束时间必须大于开始时间 |
| 单段 > 30 分钟 | 400 | 单段不能超过 30 分钟 |
| `end` 超过影片时长 | 400 | 结束时间超出影片时长（约 X 分 Y 秒） |
| `kind` 非法 | 400 | 类型只能是 marker 或 favorite |
| `color` 格式错 | 400 | 颜色格式应为 #rgb 或 #rrggbb |
| `label` > 40 字 | 400 | 标签最多 40 个字 |
| 单个标签 > 20 字 | 400 | 单个标签最多 20 个字 |
| 标签数 > 8 | 400 | 一个标记最多 8 个标签 |
| 单片已达 50 条 | 400 | 最多只能标记 50 段，请先删掉不用的 |

- 时长口径：优先 `watch_progress.duration`（真实播放过的时长），其次 `movies.runtime * 60`；两者都取不到（在线片未播过）则跳过时长校验，只保留下限与 30 分钟上限。
- 中文文案直接透传到前端 toast，不在前端二次映射，避免两套措辞。

### 4.3 缩略图接口

`GET /api/covers/marker/{movie_id}/{fname}`：

- `os.path.basename(fname) != fname` → 404（拒绝任何路径穿越）；
- 文件不存在 → 404「素材不存在」；
- 命中 `.jpg` 返回 `image/jpeg`，命中 `.mp4` 返回 `video/mp4`，并 `os.utime` 更新 mtime（LRU 清理时优先保留看过的片段）；
- 前端 `'/api/covers/' + marker.thumb` / `marker.preview` 直接当 `<img src>` / `<video src>`。

### 4.4 标记墙查询

`GET /api/markers?page=1&page_size=24&tag=<标签1>,<标签2>&movie_id=0`

| 参数 | 默认 | 说明 |
|---|---|---|
| `page` | 1 | 从 1 开始，小于 1 按 1 处理 |
| `page_size` | 24 | 1–100，超出截断 |
| `tag` | 空 | 逗号分隔（也接受 `，、;；`），OR 匹配；最多 16 个；大小写去重 |
| `movie_id` | 0 | 大于 0 时只看该片（详情页 / 排查用） |

响应：

```json
{
  "ok": true, "total": 42, "page": 1, "page_size": 24,
  "selected_tags": ["颜射"],
  "items": [{
    "id": 53, "movie_id": 857, "start": 754.0, "end": 784.0,
    "label": "名场面", "kind": "marker", "color": "", "primary": true,
    "thumb": "marker/857/53.jpg", "preview": "marker/857/53.mp4",
    "tags": ["颜射"], "created_at": "...",
    "movie": {"id": 857, "code": "ABC-123", "title": "..."}
  }],
  "tags": [{"name": "颜射", "count": 12}]
}
```

- 排序固定为 `created_at DESC, id DESC`（最新标记在前），不开放排序参数；
- 归档影片（`movies.archived_at` 非空）不出现在墙上，也不计入 `total`；
- `tags` 分面只统计 `movie_marker_tag`，不受已选标签影响（否则选一个标签后只剩它自己），按出现次数降序取前 40；
- 缺缩略图时 `thumb` 为空串，前端显示 ▶ 占位；缺少预览短片时 `preview` 为空串，卡片保持静图；两者都会顺手补（见 5.3 / 5.7）。

## 5. 交互设计

### 5.1 打点：`M` 键与 ⚑ 面板同一动作

- 播放器中按 `M`（无 Ctrl / Meta / Alt 修饰）：起点 = 当前 `currentTime`，终点 = `min(总时长, 起点 + 30)`，立即 POST，成功后本地插入、toast 提示；
- ⚑ 面板里「＋ 标记精彩时刻 `M`」调用同一个 `addMoment()`，键位提示写在按钮上，让用户发现快捷键；
- 打点不暂停、不弹表单；命名与标签在事后编辑。

### 5.2 ⚑ 面板内的标记卡片

| 区域 | 内容 |
|---|---|
| 缩略图 | 有 `thumb` 显示图，无则 ▶ 占位；角标显示起点时间；有 `preview` 时鼠标悬停改播静音循环短片，移出即停并卸载 |
| 标题行 | `label`，空则显示「精彩时刻」默认名 |
| 区间 | `mm:ss – mm:ss` 等宽数字 |
| 标签 | chips，超出换行 |
| 操作 | ★ 设/取消主标记、✎ 就地编辑、✕ 删除 |
| 点击卡片主体 | `currentTime = start` 并关闭面板 |

编辑态在卡片内展开：label 输入、start / end 数字输入、tags 输入（逗号分隔），保存走 `PUT`（只传变化字段亦可，前端一次性传全量）。删除无二次确认（面板类轻量操作，且代价低），详情页删除同样即时生效；文案为 `markerDeleted`。

### 5.3 缩略图 / 预览短片异步生成

| 时机 | 行为 |
|---|---|
| 新建标记 | 插入成功后 `submit_task(_fill_assets, movie_id, id, start)`，只生成缺的那份（缩略图 + 预览），请求立即返回 |
| 修改起点 | 仅当 `|新起点 - 旧起点| > 1e-6` 时 `_fill_assets(..., force=True)` 重抽缩略图并重转预览；改标签 / 主标记不跑 ffmpeg |
| 老标记（缺 `thumb` 或缺 `preview`） | `GET` 列表时最多挑 3 条补素材；`_PENDING` 集合去重，防止反复刷新反复排队；只对存在本地可播文件的影片生效 |
| 标记墙缺素材 | 每次列出一页最多挑 4 条补（`_backfill_page`），按 `movie_id` 缓存「是否有本地文件」，其余规则同上 |
| 在线 / 串流片 | 直接跳过，`thumb` / `preview` 留空，前端显示占位或静图，不报错 |
| 任何失败 | `_make_thumb` / `_make_preview` 内部 `try/except: pass`；打点本身已经成功，缺素材不影响任何操作 |

抽帧参数：`ffmpeg -ss <秒> -i <源> -frames:v 1 -vf scale=320:-2 -q:v 4`，输出 `data/covers/marker/<movie_id>/<marker_id>.jpg`（≤ 320px 宽、只缩不放，符合 `AGENTS.md` 海报 / 缩略图约定）。

预览参数：`ffmpeg -ss <秒> -t 4 -i <源> -an -vf scale=480:-2 -c:v libx264 -preset veryfast -crf 30 -pix_fmt yuv420p -movflags +faststart`，输出同目录 `<marker_id>.mp4`（4 秒、无音轨、宽 480、H.264 + faststart 便于边下边播）。落盘后再回写相对名，前端列表刷新（2 秒一次，缺 `preview` 时 4 秒后再补一次）才看到素材，属预期。

清理：每次生成完调用 `_prune_previews()`，按 `data/covers/marker/*/*.mp4` 的 mtime 从旧到新删到总量 ≤ `markers.preview_limit_mb`（默认 200 MB，0 = 不限制），同时把 DB 的 `preview` 置空回退静图。`GET /api/covers/marker/.../<id>.mp4` 命中时 `os.utime` 一次，所以「最近播放过」的片段不会被优先清掉。

### 5.4 进度条分层

同一 `.vjs-progress-holder` 内三层叠放，`z-index` 从低到高：

| 层 | 类名 | z-index | 内容 | 配色 |
|---|---|---|---|---|
| 1 | `.vp-ranges` | 1 | 缓存蓝 + 已缓冲浅白 | 现有变量 |
| 2 | `.vjs-play-progress` | 2 | 已播进度（video.js 原生） | 白 |
| 3 | `.vp-marks` | 3 | 标记区间子条 | 琥珀；主标记亮黄 + 白边 + 光晕 |

- `.vp-marks` 整体 `pointer-events: none`，子条 `pointer-events: auto` 且 `stopPropagation`，因此既不挡 video.js 原生拖动 / 点击 seek，又能单独响应点击跳转；
- `paintRanges()` 末尾调用 `paintMarkers()`，暂停、拖动、切清晰度、加载完标记后都重画；
- 进度条 hover 预览：指针时刻落在某个带 `preview` 的标记区间内时，预览气泡从静态帧切换为该标记的 mp4（静音、循环、`playsinline`、`preload="metadata"`，160×90 与静帧同尺寸）；移出区间回到静态帧，移出进度条暂停并卸载 `src`。浮层只复用一个 `<video>`，快速划过多个标记不堆积实例；没有 `preview` 的标记仍走静态帧；
- `kind === 'favorite'` 的子条额外加类，便于后续换色而不改结构。

### 5.5 详情页标记区

- 位置：详情页信息区内的「精彩时刻」小节，`markers.length` 为 0 时不渲染（不占位）；
- 每行：缩略图（无图 ▶ 占位）、`mm:ss – mm:ss`、label、标签 chips、★（设主标记）、✕（删除）；
- **整行可点**：点击行 = 打开详情页内嵌播放器并从该标记起点开始播。未展开播放器时把起点写进 `playFrom`，经 `VideoPlayer` 的 `start-at` 在元数据就绪后 seek；已经在播时不重建播放器，直接复用 `avm-seek` 事件跳转。播放器收起即清空 `playFrom`，下次正常播放仍回到上次进度。行内 ★ / ✕ / 标签 chip 均 `stopPropagation`（`@click.stop`），不会误触播放；
- **点击后滚动到播放器**：播放器在抽屉顶部、标记区在下方，点完必须让画面进入视野。滚动容器是 `.dd-content`（`overflow-y:auto`，不是 window），抽屉头部在滚动区之外，无需再减头部高度；播放器刚挂载时等两帧拿到真实高度再滚（高度仍为 0 则最多重试 3 次 ×150ms），已在视野内（上下各留 12px）则完全不滚，连续点不同标记不会来回晃。不做吸顶（sticky）：播放器内部有绝对定位的 ⚑ / ⚙ / 清晰度浮层与 video.js 全屏，吸顶会引入新的层叠上下文并可能遮住这些浮层；
- 悬停行内缩略图时播放该标记的 `preview` 短片（有才播，静音循环），移出即卸载；同屏只挂一个 `<video>`，触屏或无预览时保持静态图；
- 可点提示只做 hover 背景高亮 + `cursor: pointer` + 焦点描边，不加额外按钮；移动端轻点行等同播放；
- 标签 chip 可点：跳到标记墙并按该标签筛选（`state.markersFilter`，消费即清空），看同标签的跨影片片段；
- 删除后重新 `GET` 一次列表，让后端「扶正」的结果（★ 换到另一条）与界面一致，避免本地删除与主标记状态不同步；
- 不提供新增：新增只在播放器里（要先有播放位置才有意义）。

### 5.6 与片头片尾跳过共存

| 规则 | 说明 |
|---|---|
| 数据互不影响 | `movies.skip_intro / skip_outro` 是整片级单点；`movie_markers` 是片段级多区间 |
| 入口合并 | 同一个 ⚑ 面板：先渲染片头 / 片尾 / 清除，再一条分隔线 + 「＋ 标记精彩时刻」+ 标记列表 |
| 行为互不影响 | 跳过逻辑照旧按 `skip_intro / skip_outro` 触发，标记不参与自动跳过（标记是「回看点」，不是「跳过点」） |
| 已知边界 | 若某段标记与片头区间重叠，进度条上会叠色，但两者语义不同，不做去重 / 裁剪 |

### 5.7 标记墙（P1）

| 项 | 设计 |
|---|---|
| 入口 | 顶栏「更多」下拉 / 移动端导航的「精彩时刻」（`state.js` 的 `NAV_MORE` 探索组，图标 `markers`），不占主导航位 |
| 布局 | 缩略图网格 `repeat(auto-fill, minmax(240px, 1fr))`，卡片 16:9 图 + 信息区；窄屏降到 150px 两列 |
| 卡片 | 图上左下角起段时间、右上 ★ 表示主标记、无图显示 ▶ 占位；信息区为番号（无番号回落标题）、起止时间、label、标签 chips；有 `preview` 时悬停改播 4 秒静音循环短片，移出即卸载（同屏只挂一个 `<video>`），触屏 / 无预览保持静图 |
| 点击 | `state.currentId = movie_id` + `state.aiSeek = { id, seconds: start, n: Date.now() }`，沿用「AI 时间戳 / 相似推荐」那条跳转链路：打开详情页的内嵌播放器并 seek 到该秒 |
| 标签筛选 | 顶部 chips 来自 `movie_marker_tag` 词表 + 出现次数，多选 OR；卡片上的标签也可直接点选；有选中时出现「清除标签筛选」；切换筛选回到第 1 页 |
| 分页 | 每页 24 条，复用 `Pager`；翻页后滚回顶部 |
| 从详情页进入 | 详情页标记的标签 chip 点击 → `state.markersFilter = 标签` + `state.view = 'markers'`；标记墙挂载或监听时消费该值、选中对应标签并清空，避免下次从导航进入还残留筛选 |
| 空态 | 「还没有标记」/「没有符合标签的标记」两种文案，均给出「在播放器里按 M」的引导 |
| 样式复用 | `PageHead` / `Pager` / `.chip` / `.btn`，不引入新 UI 框架与新的全局样式文件 |
| 与影片 facet 的边界 | 只读 `movie_marker_tag`，不写 `movie_tags`；标签筛选不回写影片库筛选状态 |

## 7. 风险与约束

| 风险 | 现状与应对 |
|---|---|
| 50 条上限 | 服务端硬校验（含中文提示），列表接口回传 `max`；进度条在 50 段时仍可辨认（每段按秒数比例）；上限是常量，不开放配置 |
| 缩略图磁盘占用 | 单张 ≈ 8–15 KB（320px、q4），50 段 ≈ 0.5–0.75 MB/片；不生成多尺寸、不做雪碧图；删除标记时同步 `unlink`，删影片由目录清理兜底 |
| 主标记唯一性并发 | 接口「先清后写」+ 部分唯一索引双保险；极端并发下会因索引冲突返回 500，而不是写入两条主标记 |
| 在线影片取不到时长 | `_movie_duration` 两级回退（`watch_progress.duration` → `runtime*60`），都为空时跳过时长校验，只保留「end > start」与 30 分钟上限；在线片不生成缩略图 |
| 旧标记补图时机 | 单片列表每次 ≤ 3 条、标记墙每页 ≤ 4 条、`_PENDING` 去重、仅限有本地文件的影片；避免任何刷新都触发 ffmpeg 风暴；补不完下次再看继续补 |
| 抽帧与播放抢资源 | 走短任务池（4 线程，秒级 IO），不占长任务池；`timeout=30`，超时即放弃 |
| 预览短片磁盘占用 | 单条 ≈ 100–150 KB（4 秒 / 480px / crf30）；默认上限 200 MB ≈ 1300+ 条，超出按 mtime LRU 清理并回退静图；可在设置页关掉生成，已有文件不主动删 |
| 预览生成与播放抢资源 | 与缩略图同走短任务池，`timeout=60`；同一标记 `_PENDING` 去重；失败静默，不影响打点 |
| 同屏多个 `<video>` | 前端用单一 `hoverKey` 控制，任何时刻只挂载一个 `<video>`；`mouseleave` / ⚑ 面板关闭即卸载，触屏不启用悬停播放 |
| 删除主标记后的空窗 | 删除时同事务内把最早一条扶正；前端删除后重新拉列表对齐 ★ 状态 |
| 播放器改动面大 | 只新增状态 / 函数 / 模板块与 scoped 样式，未触碰缓冲、预取、跳过、字幕等既有逻辑；标记绘制挂在既有 `paintRanges()` 末尾 |
