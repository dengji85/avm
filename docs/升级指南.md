# 片匣 (AVM) 升级指南

> 本文档说明片匣的数据安全模型、自动备份机制，以及**升级 / 迁移 / 回滚**的标准操作流程。
> 目标：无论怎么升级、换电脑、重装，你的收藏、设置、观看进度都不丢。

---

## 1. 数据存放在哪（核心前提）

片匣遵循**「程序与数据同目录」**原则：

| 场景 | 数据目录位置 |
| --- | --- |
| 打包版（`dist/片匣/片匣.exe`） | `片匣.exe` 同级的 `data/` 文件夹 |
| 源码版（`python run.py serve`） | 项目根的 `data/` |

`data/` 内含：

```
data/
├── library.db        # 主数据库（收藏、元数据、评分、进度、片单等）
├── config.json       # 用户设置（含 app_version 版本号）
├── covers/           # 影片封面图
├── avatars/          # 女优头像
├── bg/               # 自定义背景图
├── nfo/              # 本地 .nfo 离线元数据
└── library.db.bakYYYYMMDD   # 自动每日备份（见下）
```

> **结论**：`data/` 就是你的全部家当。**只要 `data/` 在，一切都还在。**

---

## 2. 自动备份机制（程序内置）

自 v1.1.0 起，程序每次启动会自动执行一次轻量备份：

- **触发**：后端服务启动时（`app/main.py` 的 `_backup_database()`）。
- **内容**：复制 `data/library.db` 为 `data/library.db.bakYYYYMMDD`（按当天日期命名）。
- **频率**：同一天只备份一次（同名文件已存在则跳过），不会越攒越多。
- **清理**：自动删除 **超过 7 天** 的旧备份。
- **安全**：备份逻辑全程异常吞掉（try/except），即使备份失败也**不影响程序正常启动**。

另外，`config.json` 若损坏，配置加载层会自动用缺省值重建并保留 `.bak.json` 副本（`app/config.py` 行为）。

> 备份是「多一层保险」，不是替代手动备份。重要收藏建议额外把 `data/` 拷到移动硬盘或网盘。

---

## 3. 版本记录

程序在 `config.json` 写入 `app_version` 字段（由 `_record_version()` 维护）：

```json
{
  "app_version": "1.1.0",
  "scan_dirs": ["D:/AV"],
  ...
}
```

用途：
- 便于用户确认当前运行版本。
- 为将来大版本 schema 变更时的迁移提示预留钩子（当前各版本 schema 兼容，无需手动迁移）。

---

## 4. 升级步骤（同机器）

### 方式一：覆盖 exe（推荐）

1. 下载新版 `片匣-<版本>-win64.zip`。
2. 解压得到 `片匣/` 文件夹。
3. **用里面的 `片匣.exe` 覆盖旧的 `片匣.exe`**，旧目录里的 `data/` 文件夹**原样保留、不要动**。
4. 双击新 `片匣.exe` 启动。

启动后程序会自动：
- 备份当天 `library.db`；
- 写入新的 `app_version`；
- 沿用你原有的全部收藏与设置。

> ⚠️ **不要**删除整个旧文件夹再解压——那样会连同 `data/` 一起清掉。只覆盖 exe 本身。

### 方式二：源码版

```bash
git pull            # 拉取新版代码
pip install -r requirements.txt   # 若依赖有变
python run.py serve
```
数据仍在项目根 `data/`，不受影响。

---

## 5. 迁移到新机器 / 重装系统

**最简单：整体拷贝。**

1. 在旧机器上，把整个 `片匣/` 文件夹（含 `data/`）拷到移动硬盘 / U 盘 / 网盘。
2. 在新机器上解压 / 拷到目标位置。
3. 双击 `片匣.exe` 即可，收藏、封面、设置、进度全在。

### 自定义目录的特别处理

若你在「设置 → 媒体资源路径」里把头像 / 背景图指向了**独立磁盘的绝对路径**（如 `E:/covers`），迁移时需注意：

- 目标机需**同样挂载该路径**，或
- 改回相对 `data/` 的路径（把图放进 `data/avatars`、`data/bg`），避免找不到图。

`scan_dirs`（要扫描的影片目录）同理：换机后路径变了，需在设置里更新。

---

## 6. 回滚到旧版本

若新版有问题，想退回旧版：

1. 保留当前 `data/`（含最新 `library.db` 与 `.bak*`）。
2. 用旧版 `片匣.exe` 覆盖新 exe（数据兼容，向下兼容）。
3. 若担心新版改了数据库结构导致旧版读不了，可先**用当天的 `library.db.bakYYYYMMDD` 还原**再回滚：
   ```powershell
   cd 片匣\data
   copy library.db.bakYYYYMMDD library.db
   ```

---

## 7. 故障恢复速查

| 现象 | 处理 |
| --- | --- |
| 启动后收藏变空 | 先看 `data/` 是否被误删；若 `library.db` 损坏，用最近的 `library.db.bak*` 覆盖还原 |
| 设置丢失 | `config.json` 损坏会自动用 `.bak.json` 兜底；必要时手动改回 |
| 升级后封面/头像不显示 | 确认 `data/covers`、`data/avatars` 随 exe 一起保留；路径改为相对更稳 |
| 换机后扫不到影片 | 在设置里把 `scan_dirs` 改到新机器上的实际影片路径 |

---

## 8. 发布者须知（打 Release 包）

如果你是维护者 / 要给别人发新版：

1. **打包**：
   ```bash
   python build.py        # 产物 dist/片匣/片匣.exe
   ```
2. **压缩**：把 `dist/片匣/` 压成 `片匣-<版本>-win64.zip`。
3. **发 Release**：GitHub → Releases → New，tag 用 `v<版本>`（如 `v1.1.0`），把 zip 作为附件。
4. **Release 说明必写**（避免用户丢数据）：
   > 升级：下载后**用 `片匣.exe` 覆盖旧 exe**，保留同目录的 `data/` 文件夹，收藏与设置全部保留。
   > 换电脑：直接拷贝整个 `片匣` 文件夹即可。
5. **数据文件不入库**：`data/`、`dist/`、`*.zip` 已在 `.gitignore` 忽略，Release 包只走 GitHub Releases，不进 git。

---

## 9. 设计原则小结

- **数据随程序目录走** → 拷贝即迁移，无外部依赖。
- **启动即备份** → 每日一份 `library.db` 快照，7 天滚动。
- **覆盖即升级** → 不删 `data/`，收藏永不失联。
- **配置容错** → 损坏自动兜底，服务不崩。

> 一句话：**你只要记得「别删 data/ 文件夹」，就永远丢不了数据。**
