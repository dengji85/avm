## 😩 你有没有这些「收藏老毛病」？

- 硬盘换了一茬又一茬，**存了上千部，却根本找不到**想看的那一两部
- 同一部片在库里**躺了七八份**：无码版、有码版、中字版、压片版……占空间还分不清
- 文件名是 `IRO061C`、`SONE-760CH`、`300MAAN-123` 这种**野路子命名**，普通工具一概识别不了
- 封面张冠李戴、刮削失败，**素人片连封面都没有**
- 「上次那部女主是老师的」——**靠脑子想，想不起来**
- 看到一半被打断，**进度丢了，下次从头来**
- 怕隐私泄露、怕平台关站、怕换电脑收藏全没了

**片匣就是专门给资深爱好者治这些毛病的。**

## ✅ 为什么需要片匣

一句话：**你的收藏，值得一个像样的「图书馆」，而不是一堆文件夹。**

| 没有片匣 | 用了片匣 |
| --- | --- |
| 文件命名混乱，靠记忆翻找 | 番号自动归一、分面筛选 + 语义搜索，秒定位 |
| 同一部重复七八份 | 内容级去重 + 多版本归并，只留最佳版 |
| 封面缺失、刮削失败 | 多源可插拔 + 跨源回退，有番号素人片也补齐封面 |
| 看没看过全凭印象 | 零配置观看监控，自动记进度、看没看完一目了然 |
| 收藏在别人家的服务器 | 全本地、无账号、不联网上报，数据拷走即用 |

> **全程本地运行，默认不联网上报。AI 也走你自己的端点，密钥只发给你配的地址——你的收藏，始终是你自己的。**

## ✨ 核心功能

<p align="center">
  <img src="docs/assets/avm影片库.PNG" alt="AVM 系统一览" width="1100"/>
</p>

- **🗂 自动扫描建库**：递归扫描目录，自动剥离站点/发布组/技术噪声，跳过 sample/预告/回收站等；小预览片直接忽略。
- **🔍 野路子番号识别**：`IRO061C`、`SONE-760CH`、`300MAAN-123` 这类「字母紧贴数字、带版本尾巴」的命名也能归一成 `IRO-061` / `SONE-760`，并自动识别字幕(`-C`)/无码(`-U`)/VR/4K/分卷。
- **🧹 多版本归并 + 内容去重**：无码/有码/导剪/中字自动归同一部；按「大小 + 内容哈希」识别精确重复。**明显的分段（`-cd1`/`(1)`/`-a`）识别为合集，绝不误判成重复、绝不误删。**
- **🖼 元数据刮削**：可插拔数据源（JavBus / JavDB / AV-Wiki / 本地 `.nfo` / 自定义 JSON·HTML 规则），补齐封面、女优、类型、系列、厂商、评分、简介；刮不到也能手动补。
- **🤖 可选 AI 增强**：兼容任意 OpenAI 协议端点——云端填 Key，本地 Ollama 免 Key。自然语言搜「找几部有剧情、女主是老师的」直接翻出来；详情页一键生成简介、补充标签。AI 未启用自动降级为普通检索。
- **📺 零配置观看监控**：把文件丢给 VLC / PotPlayer / MPC / mpv，后台自动记「看了多久、看到哪、看没看完」；续播进度、相似推荐、「我的观影」偏好分析，下一部不纠结。
- **🩺 数据健康体检**：六类媒体问题（缺失文件 / 分片不完整 / 缺封面 / 占位图 / 未识别番号 / 疑似重复）+ 四类劣质片筛查（广告样片 / 低码率 / 同番号劣质版 / 损坏），一键保留最佳版、清理冗余。
- **🎴 画廊策展**：卡片墙 + 女优墙 + 标签云 + 智能片单（按规则自动聚合）+ 相似推荐，把「囤」变成「能翻出来看」。
- **📡 远程访问**：手机/局域网设备扫码即开，Token 鉴权 + 防火墙放行提示（`edge=yes` 边缘穿越，不关整个防火墙也能通）。
- **⏱ 定时自动扫描**：下载新片后按周期自动增量入库，不用每次手动点扫描。
- **💬 字幕匹配**：浏览器直接选字幕文件上传，按番号对齐重命名，系统播放器打开即加载。

## 🆚 为什么选片匣而不是别的工具

市面方案大致两类：**通用媒体刮削器**（TinyMediaManager、MediaElch、XBVR 等——影视为主，AV 只是勉强兼容）和**各种 JAV 小脚本**（能力单一、无界面）。片匣是**专为 AV 收藏做领域适配的一站式本地资料库**。

| 你真正在乎的 | 通用刮削器 | 自建脚本 | **片匣 AVM** |
| --- | --- | --- | --- |
| **野路子番号认得出？** | 通常只认规范命名 | 单源查号，无归一化 | 7 类规则专用解析，归一化 + 标记识别 |
| **同一部不再躺七八份？** | 多版本需手动归并 | 基本不支持 | 自动归并 + 内容级去重，分段不误判 |
| **AV 元数据准？** | 对 AV 编目偏弱、封面易错 | 依赖单站，挂了即空 | 多源可插拔 + 跨源回退，有番号素人片也补封面 |
| **强反爬源（AV-Wiki）？** | 不涉及 | 需手动养浏览器 | 内置 CDP 抓取，常驻 headless Chrome 自动绕过验证页（需本机已装 Chrome，否则自动回退普通请求） |
| **以「作品」而非「文件夹」策展？** | 以文件夹为中心 | 只有列表 | 女优墙 / 标签云 / 智能片单 / 相似推荐 |
| **中断能续播？** | 需播放器插件 | 无 | 零配置监控任意系统播放器，自动记进度 |
| **库脏了能一键看清？** | 基本无 | 无 | 六类体检 + 四类劣质片筛查，一键清理 |
| **AI 语义搜索？** | 多数无 | 无 | 可选，兼容任意 OpenAI 端点 / 本地 Ollama |
| **隐私 & 部署？** | 桌面 GUI / 常驻服务 | 散装脚本 | 纯本地 Web、无账号、单命令打包免安装 exe |

> **简言之：它不是又一个「能放视频的网页」，而是为 AV 收藏这个特殊领域做了大量领域适配（番号、去重、素人、观看回归、体检）的本地资料库。**

## 🌟 本次更新亮点（1.11.0）

> 发布日期：2026-08-15

- **🔎 刮削失败原因面板**：维护中心新增「刮削失败原因」Tab，把过去「刮削失败=黑盒」变成可视化诊断。每部失败影片展示**逐源明细**（各数据源状态 + 原因）并给出整体归类与操作建议；失败按「反爬拦截 / 网络错误 / 源无此片 / 解析失败 / 番号异常」五类分组计数，一眼区分「源挂了」还是「片真没有」。
- **一键重试 + 换源重抓**：仅重跑临时性网络/拦截项（不动稳定缺失），或勾选影片指定数据源（如切到 av-wiki）重新抓取，绕过被拦站点。
- **💬 字幕匹配改为直接选文件**：维护页点「选择文件」即可上传字幕，按番号匹配库内影片并一键对齐重命名（支持复制保留原件）。
- **🧹 重复检测强化分段识别**：除 `_1`/`-cd1`/`.part3` 外，新增括号 `(1)`、`[2]`、单字母 `-a`、带分辨率 `1080p-1` 等明显分段识别；番号末位不再被误当序号。
- **🔔 关于页版本检查**：对接 GitHub Releases，显示当前/最新版本与更新说明，支持自定义更新源。
- **📡 远程访问独立 Tab**：多地址点击切换生成二维码、Token 自定义、防火墙放行提示。
- **⏱ 定时自动扫描**：按分钟周期后台增量入库。

## 📦 下载与安装

不想自己打包？直接下载发布包（Windows 单文件夹压缩包，解压即用）：

<p align="center">
  <a href="https://github.com/dengji85/avm/releases/latest">
    <img src="https://img.shields.io/github/v/release/dengji85/avm?label=下载%20最新版&color=1f6feb" alt="GitHub Release"/>
  </a>
</p>

1. 到 **[Releases](https://github.com/dengji85/avm/releases)** 下载最新 `AVM-win64.zip`。
2. 解压到任意目录（如 `D:\AVM\`），双击 `AVM.exe` 启动，自动打开浏览器进入 Web UI。
3. 数据（库 / 封面 / 配置）在 `data/` 目录，**整体拷贝即备份迁移**。

## 🚀 快速开始

### 方式一：源码运行（开发）

```bash
pip install -r requirements.txt
python run.py serve            # 后端 http://127.0.0.1:8770
cd web_src && npm install && npm run dev   # 前端 http://localhost:5173
```

### 方式二：构建后整体托管

```bash
cd web_src && npm install && npm run build
python run.py serve            # 直接托管 web_dist/
```

### 打包为免安装版

```bash
python build.py                # 生成 dist/片匣/片匣.exe
```
